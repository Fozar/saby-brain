# Корешки: фильтр по ТипСвязи и покрытие индексами

Открытые вопросы, поднятые Мусохрановым на ревью [[zvonok-musohranov-timoshenko-2026-07-23|2026-07-23]] и помеченные «странное — пометим». Отложены Тимошенко на уровень реализации.

## Вопрос 1 — зачем `ТипСвязи` при подсчёте ВСЕХ статусов?

- Для **позитивных** заявок фильтр по `ТипСвязи` (например `= 15` успех) понятен.
- Но при подсчёте **всех** статусов (10 в работе / 15 успех / 20 не успех) — зачем вообще смотреть на `ТипСвязи`?
- Тимошенко: *«перестраховка»* (отсекает записи с `ТипСвязи IS NULL`, которые не являются корешками).
- Мусохранов: это **влияет на попадание в индекс** — «большой момент», не декоративный фильтр.

## Вопрос 2 — покрытие индексами

- Итоговая выборка идёт **по конкретной карте**, а не просто по `ТипСвязи = 15`.
- Индекс `(ВидЦены, EffectiveDate)` **без Карты** → при поиске по карте не используется (`Карты IS NOT NULL, ВидЦены IS NOT NULL, Сумма IS NOT NULL` — не попадём).
- Есть отдельный индекс **только по `Карта`** и «жирный» индекс по `ТипСвязи`.
- Нужно понять, есть ли индекс, где `EffectiveDate` в паре с `Карта` — иначе позитивные по дате закрытия не лягут на индекс.

## Как проверять

Гонять запросы на **большой БД** (недавно стала доступна) — поля `ТипСвязи`/сумм заполняются и на обычных (не реф.) картах, поэтому скорость запроса можно замерить без реф. программы.
