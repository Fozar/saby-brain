# Мастер-фильтр периодов начинается не с первой заявки после ВНР истории РКО

Navigation: [[SabyBank-RKO-Referral]] | [[ReferralProgram-GetLeadPeriodList-Stub-Mode]]

**Ошибка:** https://online.sbis.ru/opendoc.html?guid=01a0b29b-63ea-777b-a389-da6b46401c0b&client=3 (№0918668, стенд, Земцова, срок 10.10, веха 26.5100)
**ВНР-исправление:** https://online.sbis.ru/opendoc.html?guid=01a1103e-95e9-70e5-a3f6-0298f36aa512&client=3 (№10064568, срок 23.10)

## Суть

В детализации банковского оффера мастер-фильтр по периоду начинается с месяца создания оффера (у владельца) или с месяца присоединения (у партнёра). После ВНР по историческим заявкам РКО (№09154446, https://online.sbis.ru/opendoc.html?guid=01a0a411-3210-7e20-9633-224df1180847&client=3, на бою прошла в ночь на 19.09) появились заявки раньше этого месяца, и их не видно в фильтре. Нужно: первый месяц = месяц первой заявки.

## Что выяснено

- Периоды строит `ReferralProgram.GetLeadPeriodList`, `get_lead_period_list.py`, CTE `start_date`: `coalesce(MIN("ДатаНач"), CURRENT_DATE)` по реферальным кодам (`Карта`) программы, с `PartnerId` по коду партнёра.
- `ДатаНач` кода ставится при присоединении: `join.py:99` `datetime.date.today()`.
- ВНР истории создала корешки с датой создания заявки из банка (`ДатаВремя = CreatedAt`), а банки-партнёры присоединились к офферу позже. Отсюда заявки до `ДатаНач`.
- Тот же `ДатаНач` использует `GetPartnerList` (`get_partner_list.py:508`, `c."ДатаНач" <= DateEnd`): за ранние периоды партнёр с заявками туда тоже не попадёт. Поэтому правка данных лучше правки одного метода, она чинит оба места.
- В живом пути `CreateStub` берёт `CreatedAt` из запроса, но без кода партнёра корешок не создаётся (Warning «не является участником»), так что новые заявки раньше присоединения появиться не должны. Риск остаётся только при повторных ВНР по истории.

## Тех. решение

Выбрано исправить данные, а не метод: ВНР №10064568 (архив `s_timoshenkoaa_10064568_v1.zip`, только ClientID 3 на всех стендах). Для каждого реферального кода (`ТипКарты = 2`) скрипт ищет самый ранний корешок программы (`ТипСвязи IS NOT NULL`, `MIN("ДатаВремя")::DATE`) и, если `ДатаНач` позже, ставит в `ДатаНач` дату корешка. Старая и новая даты пишутся в лог ВНР.

Константы скрипта сверены с `rc-26.5100`: `PriceEntityType.REFERRAL_LEAD = 37`, `ItemNumberType.REFERRAL_CODE = 2`.

Вариант, от которого отказались (он остался в описании ошибки): в `GetLeadPeriodList` брать `LEAST(MIN(ДатаНач), первый корешок)`. Подварианты: А без индекса (медленный случай у обычной программы без корешков), Б с частичным индексом `ВидЦеныДокумент (ВидЦены, ДатаВремя)` по корешкам (на согласовании, https://dev.saby.ru/opendoc.html?guid=019fd0b4-8c8d-7848-a285-61aad8837ee5&client=3). Минус: `GetPartnerList` остался бы со старой датой.

## Открытые вопросы

- Мусохранов: согласование ВНР №10064568 висит с 06.10 (срок этапа 07.10).
- Описание ошибки до сих пор описывает правку метода (варианты А/Б). Обновить на «исправлено данными, ВНР №10064568», иначе QA и ревьюер ждут MR.
- Кода нет, поэтому ошибку дальше передавать вручную, после прогона ВНР на pre-test/fix. Сценарий для QA: владелец и партнёр банковского оффера, фильтр 2026 год, первый месяц = месяц первой заявки; в списке партнёров за ранний месяц банк виден.
- Если историю РКО придётся догонять ещё раз (новый банк присоединится позже своих заявок), ВНР по `ДатаНач` нужно прогнать повторно.

## Состояние

Код не меняется, worktree нет. ВНР собрана и приложена к №10064568, ждёт согласования.
