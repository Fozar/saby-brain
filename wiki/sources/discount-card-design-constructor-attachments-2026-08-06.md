# Дизайн ДК на конструкторе — вложения проекта, ingest 2026-08-06

Догоняющий ингест поверх [[discount-card-design-constructor-2026-07-03]], который покрыл 3 документа из 6. Вложения взяты **не из файловой выгрузки, а напрямую из карточки проекта** SBIS: `sbis_resolve_url` на `project.sbis.ru/uuid/…/page/project-main` → тип «Проект», `doc_id=552551747` → `sbis_list_attachments` → 13 вложений.

> [!note] Метод доступа переиспользуем
> Для типа «Проект» у MCP `sbis` нет отдельного ридера (`sbis_resolve_url` отвечает «тип распознан, инструмента нет»), но выдаёт `doc_id` — и `sbis_list_attachments` по нему работает штатно. То есть вложения любого проекта достаются в два вызова. Файлы `.sabydoc` приходят **без расширения** — конвертер `convert_sabydoc_to_markdown` требует его дописать вручную; часть документов вообще не zip-`.sabydoc`, а «голый» JSON старого формата (`{name, meta, frame, body}`) — читается обходом дерева `frame`.

## Что проверено и оказалось пустым

**`Сравнение с конкурентами` и `Эксплуатация системы` — незаполненные шаблоны.** Оба приложены «Администратором системы» 2026-01-25, содержат только рыбу («Все жёлтое должно быть заполнено», «Понятие – описание», «Сравниваемый функционал / СБИС / Система конкурента»); у первого `lastEditDate` — февраль 2025, то есть это общекорпоративный шаблон, а не документ проекта. Пробел из ингеста 2026-07-03 («не читались») закрыт отрицательным результатом — перечитывать незачем.

## Расхождение план vs смета

`Сравнение.xlsx` — рабочая сверка автора проекта: план работ и плановая смета разошлись по дням у 8 участников (Кузаков +3,5; Курников +2,5; Ютман +3; Романова +1; Омельяненко −2; Михель −2; Лебедева −1,5; Барышева −1) и 7 человек из плана вообще отсутствовали в участниках сметы (Стригин 4,5 д; Тютюник 2 д; Перевозчиков 2 д; Бритнев 1,5 д; Агафонцев 1 д; Матюшев 1 д; Романова А. 1 д). В итоговой смете все они присутствуют → сверка была отработана. Суммарно: план работ **252,5 чд**, смета **251,5 чд**.
