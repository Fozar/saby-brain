# Скрипты (DeveloperScript) — полная статья

Полная официальная статья базы знаний СБИС/Saby «Скрипты» (раздел «Система обновлений»), сохранённая через Obsidian Web Clipper 12.06.2026. Более подробная и полная версия материала, частично уже покрытого страницей [[wasaby-infra-2026-04-12]] (файл `Скрипты.md` в той батч-подборке).

## Содержание источника

- Определение скрипта и файла скрипта (архив с `.orx` + `DeveloperScript`), процесс вызова через Хоттабыч → DWC → `DeveloperScript.ExecuteAll`, лексикографический порядок методов, `TenantContext` для персональных сервисов
- Инструкция для разработчиков: подготовка `.orx` через Genie, создание архива (7-Zip, CP866), требования к сервису-исполнителю, правила именования модуля `DeveloperScript_<Уникальное_имя>`
- Инструкция для эксплуатации: внедрение на сервис, режим запуска (копия/минимальный сервис), параметры ВНР
- **Отчёт выполнения скрипта**: расположение (реестр Обновления), статусы (Успешно/Ошибка/Не выполнено), пример online-ru (183044 клиента, 670 прервано), шаринг ссылки на отчёт
- **Анализ выполнения**: логирование под методом `DeveloperScript.ExecuteAll`, формат меток `[script][start]`/`[script][finish]`, проверка асинхронных очередей на фазе очистки, поведение «Возобновить» vs запрещённое «Принудительно завершить»
- **Сохранение результатов**: `LogRedis` (≤5 МБ/клиента, Redis, online/inside) vs файловые логи `LogMsg`/`LogArrayMsg`/`LogsDirectory` (без ограничения объёма, диск БЛ)
- **Типичные задачи**: выполнение на конкретных клиентах (файлы `*_cloud_clients`/`*_billing_clients` по стендам — полная таблица имён), список сервисов для неперсональных приложений (`services`), разный код на разных стендах (`CloudEntity.SysName()`), CONCURRENTLY-индекс без транзакции, **запрос на схеме public без pgbouncer** (прямое соединение через `clusters.direct_db_connections`), выполнение по всем БД сервиса (`Invoker.ExecuteOnDatabase` + `FutureInvoke`), выполнение на схеме public (`BeforeScript`/`AfterScript`), получение файлов модуля (2 способа), ограничение одновременного выполнения (**диапазон 0–999**, лимит 300 000 сценариев DWC), число рабочих процессов, частичное/повторное выполнение (уникальность по хэш-сумме архива), локальная проверка

## Key Insights

- **Диапазон «Ограничение одновременного выполнения» — 0–999**, а не 0–100, как было ранее записано на [[Wasaby-Scripts]] по данным более раннего частичного клиппинга. См. `> [!contradiction]` на [[Wasaby-Scripts]].
- **Прямое соединение с БД обязательно для запросов на схеме `public`** (например, для типа `hstore`) — через `pgbouncer` запрос может уйти в другое соединение, и `SET search_path` не подействует на тот запрос, для которого он предназначен.
- Число одновременно исполняющихся скриптовых сценариев DWC ограничено практическим потолком **300 000** — иначе исполнение скрипта нужно делить на несколько этапов по дням.
- Отчёт выполнения скрипта хранится в реестре «Обновления» и доступен по shareable-ссылке любому пользователю с минимальными правами, без доп. авторизации.
