# Диалог: разбор реализации UI истории изменений реф. программы

Источник: `raw/Диалоги SBIS/019f1c60-d761-7b2b-95fa-3ab61865088c.md` (theme_id `019f1c60-d761-7b2b-95fa-3ab61865088c`), сообщение Тимошенко → Лебедева Наталья, 2026-07-29 16:20.

Реализационный разбор постановки [[ReferralProgram-History-UI-Design]] (решение по 2 звонкам 2026-07-29 уже задокументировано отдельно). Тимошенко зафиксировал в задаче конкретный разбор «кто что делает» и прислал сжатую версию Лебедевой Наталье.

## Три пункта

1. **Кнопка истории корешка** — в карточке заявки, и, возможно, на ховере строки в реестре. Объект — `ReferralStub`. Идентификатор — `guid`-строка, это `RequestUUID` (уже есть в строке реестра).
2. **Клик по «Создана заявка №…» в истории оффера → история этого корешка.** Механизм — опция `instanceClickCallbacks` (ссылка на статью базы знаний, раздел toc_45185059). UUID корешка Тимошенко положит в событие клика через `Attributes->RequestUUID`.
3. **История из реестра офферов — через БЛ-метод Тимошенко.** Сейчас метод без фильтра показывает всё по аккаунту; будет доработан фильтром по текущей реф. сети, формат ответа — как у платформенного метода. Метод — `ReferralProgram.GetHistoryList`.

## Кто что делает

- **Тимошенко**: пункт 2 (событие клика, UUID корешка в `Attributes`) и пункт 3 (фильтрация БЛ-метода `GetHistoryList` по реф. сети).
- **Лебедева Наталья**: пункт 1 (кнопка истории корешка в карточке/ховере) и использование метода из пункта 3 на фронте.

## Открытое

Разбор фиксирует «как делать», но не подтверждает завершение реализации ни одного из трёх пунктов — статус на момент сообщения: договорённость о разделении работ, реализация в процессе.
