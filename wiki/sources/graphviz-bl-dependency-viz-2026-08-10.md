# Визуализация зависимостей модулей БЛ дистрибутива онлайна с помощью Graphviz

Внутренняя новость/пост dev.sbis.ru (автор [[Садомов-А.А.]]) о самодельном инструменте для визуализации зависимостей БЛ-модулей дистрибутива онлайна через [Graphviz](https://graphviz.org/).

## Содержание источника

- Контекст: анализ транзитивных зависимостей модуля Cadres от «Зарплата и кадры» (ЗиК), с целью планируемого рефакторинга — вынести общий функционал в новый модуль SalaryCore и заменить `Cadres → ЗиК` на `Cadres → SalaryCore`
- Отсутствие готового внутреннего инструмента для этой задачи (искал недолго — «было лень их вызванивать»)
- Использование open-source Graphviz: генерация текстового описания графа (`.gv`, DOT-формат)
- Пример DOT-описания графа прямых зависимостей Cadres (14 узлов, UUID + label, рёбра зависимостей)
- Собственный инструмент `S3modToGraphviz`: генерирует DOT-описание зависимостей для БЛ-модулей дистрибутива онлайна из `*.s3mod`-файлов; параметры `s3mod_folder`, `target_folder`, `--specific_module`
- Установка: graphviz (rhel9) + python-пакет graphviz
- Три уровня примеров картинок: прямые зависимости Cadres (SVG), все транзитивные зависимости Cadres (SVG, крупнее), граф всех зависимостей онлайна версии 26.4100 (очень большой)
- Код: `git.sbis.ru/aa.sadomov/sandbox/-/tree/master/S3modToGraphviz`
- Автор в конце спрашивает у читателей идеи практического применения — то есть на момент публикации у инструмента нет закреплённого продуктового применения за пределами разовой оценки

## Key Insights

- Первый зафиксированный в вики прецедент **визуализации графа зависимостей БЛ-модулей** дистрибутива онлайна — до этого источника вики знала только декларативную сторону s3mod-зависимостей ([[Wasaby-Module-System]]), но не инструментарий для их анализа/визуализации.
- Инструмент — sandbox-уровня (личный git-репозиторий автора), не часть официального тулинга платформы; отдел сборки/платформы, по словам автора, потенциально имеет аналогичный инструмент, но это не проверено.
- Мотивирующий кейс — конкретный, измеримый рефакторинг: `Cadres → ЗиК` (легаси-зависимость от исторически более крупного модуля «Зарплата и кадры») переходит в `Cadres → SalaryCore` (новый, более лёгкий, выделенный модуль), совместно с командой зарплаты.

## Что НЕ покрыто источником

- Нет описания алгоритма разбора s3mod-файлов (как именно вычленяются зависимости из XML/декларации)
- Нет данных о принятии инструмента другими командами или о его судьбе после публикации поста
- Модули «Зарплата и кадры», SalaryCore, Cadres упомянуты только по названию — без описания их функционала, кроме кадрового учёта в общих чертах
