## Содержание и договорённости

### 08:11–08:14 — Остаток лицензирования промокодов

Закончить переход на новый хелпер. В общем хелпере проверить обработку недоступности биллинга: логировать ошибку связи и не блокировать сохранение промокода. Это не разрешение игнорировать отсутствие лицензии. Связанную ошибку привязать к задаче, затем можно закрыть дублем. См. [[Loyalty-License-Dispatcher-PromoCode-Migration-09281060]].

### 08:14–08:15 — Документация

Начать заранее, потому что согласование может занять много календарного времени. Работать с Александром; по карточке поручения — Алябушев А.А. Описана практика дальнейшего представления результата Юрию через Александра. См. [[PromoCode-Algorithms-Processes-Documentation-11028176]].

### 08:15–08:20 — Виджеты и API наших компаний

Передавать фильтры ТП и типов заведений API НК, получать конкретные ID и по ним отбирать агрегаты виджета. Свою выборку по таблицам НК убрать. По API обращаться к Максиму Милованову, по агрегатам — к Святославу Постнову. См. [[LoyaltyWidgets-OurCompanies-API-11011809]].

### 08:20 — Повторное ревью

Тимошенко сообщил о rebase и повторной отправке исправления после проблем фронтенда. Вероятное соответствие по порядку плана — [[PromoCode-Gift-Choice-Description-10127356]], но номер не произнесён. Новые MR из этой реплики не устанавливаем.

### 08:21–08:24 — Тип выгоды и синхронизация франшизы

Если были бонусные операции, менять тип выгоды больше нельзя даже после подтверждения; использовать существующую точку проверки. См. [[BonusProgram-Profit-Type-Change-Block-10306450]]. По пороговым акциям подробностей нет: уточнить объём поддержки, см. [[Franchise-Threshold-Promotions-Sync-102912590]].

### 08:24–08:31 — Лицензии внешних бонусных систем

Лицензия внешней системы покупается на аккаунт, а не на количество ТП. В отличие от балансных параметров она требует отдельной логики биллинга/диспетчера; Матюшев не уверен, что всё уже предусмотрено архитектурой. Общий порядок: параметр → биллинг и диспетчер → кэш и проверки в конкретных сценариях.

Три задачи: регистрация PremiumBonus, открытие смены, выбор клиента. Желательно сделать максимум в ноябре для декабрьского тестирования. По исходному плану проекта с 15 января открывают часть пользователей, в 27.1100 — всех; год января следует из контекста (2027), в речи не назван. Команда готова рискнуть именно этими менее критичными сценариями, но не хочет выпускать их без тестирования. Перед технической реализацией прийти к Матюшеву обсудить детали.

### 08:31–08:35 — Рабочий процесс

Матюшев после запуска плана проверяет пропущенные тесты по участкам и при необходимости заводит отдельную задачу/поручение на снятие skip, привязанную к общему поручению. Получатель ещё не определён.
