# Mindbox

Внешняя коммерческая **CDP-платформа** (Customer Data Platform / маркетинг-автоматизация) — `mindbox.ru`. В вики упоминается как **конкурентный референс/бенчмарк**, изучаемый командой Tensor/Saby при проектировании собственной системы триггерных сценариев лояльности ([[CustomerJourney-Scenarios-Project]]), а не как интегрируемый продукт.

## Продукт: сценарийный конструктор (workflow builder)

UI-конструктор автоматизационных сценариев на основе узлов (blocks), наблюдаемый в скриншотах:

| Тип узла | Назначение |
|----------|-----------|
| **Событие** (Event) | Запуск сценария по клиентскому событию (категории см. ниже) |
| **Расписание** (Schedule) | Запуск по времени: каждый день / по дням недели / по дням месяца, + условия запуска |
| **Условие** (Condition) | Ветвление по фильтрам клиента/заказа/продукта (да/нет) |
| **Группа шагов** | Блок действий (например, «Отправить брошенную корзину») |
| **Разделение** | Сплит-тестирование/ветвление трафика |
| **Ожидание** | Пауза (например, 30 минут, с окном исключения по времени суток, напр. `08:00–22:00`) |
| **AB-тест** | A/B-тестирование сценария |
| **Ограничение** | Лимиты запуска |

Пример из источников: сценарий «Брошенная сессия» (833, черновик) — `Событие: Окончена сессия → Ожидание 30 мин (окно 08:00–22:00) → Условие: сутки без заказа + есть рассылка/подписка/валидность → Условие: в сессии есть добавление в корзину → [да: Группа шагов «Отправить брошенную корзину»] / [нет: Условие «в сессии есть просмотр продукта» → …]`.

Технический механизм: клиентская **сессия** закрывается автоматически через 30 минут бездействия либо принудительно JS-командой `mindbox("closeSession")`; за сессией отслеживаются действия (добавления в список продуктов, просмотр продукта/категории), см. `help.mindbox.ru/docs/workflow-session`.

## Контекст использования в источниках

Команда анализирует не только админку Mindbox, но и реальный чек-аут флоу интернет-магазина (сайт ресторана «Мили», `mili-rest.ru`), построенный поверх Mindbox-подобной механики, задавая вопросы о том, **в какой момент клиента следует авторизовывать** относительно наполнения корзины — открытый вопрос при проектировании собственного сценария «Брошенная корзина» (см. [[AbandonedCart-Loyalty-Scenario]]).
