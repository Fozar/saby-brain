# Сумма по сделкам в корешках — поле «Сумма» ВидЦеныДокумент

## Проблема

Виджет/реестр `GetPartnerList` показывает по каждому партнёру колонку **«сумма по сделкам»**. Но корешок (`ВидЦеныДокумент` с `ТипСвязи IS NOT NULL`) сейчас несёт **только статус (`ТипСвязи`) и вознаграждение (`Бонусы`)** — величины сделки в нём нет. Для обычных программ под фичей партнёры из маркетинга приходят уже с суммой, а по корешкам её негде взять → статистика «не сойдётся».

## Решение (принято на звонке 2026-07-23)

1. **Хранить сумму в поле «Сумма» `ВидЦеныДокумент`.** Поле сейчас в подсчёте не фигурирует (`Бонусы` используются для вознаграждения, «Сумма» — свободна) → отдаём его под величину сделки.
2. **Считать `SUM` по полю «Сумма» тем же подзапросом**, где уже бежим по отобранным `ВидЦены` для `COUNT` количества. Одна строчка через запятую к существующему агрегату — отдельный проход не нужен.
3. **Пока писать пусто/ноль.** Функционал наполнения не реализован → и для SabyBank, и для обычных под фичей поле суммы по сделкам должно быть **пустым**. Явно фиксируем «не сделано», чтобы не забыть.

> [!key-insight] Сразу поле «Сумма», без отдельной сущности
> Мусохранов: «Сразу принимаем решение — храним в поле Сумма, да и всё». `SUM` встаёт бесплатно рядом с `COUNT` в том же подзапросе по отобранным `ВидЦены`. Как заполнять и в какой момент — отдельная задача, но само место хранения решено сразу.

## Отложенные подзадачи

- **Наполнение суммы.** Источник — платформенный/маркетинговый метод («у ребят»), нужна мета-информация о величине сделки. Вероятно заполняется в момент **конвертации**; метод конвертации тоже придётся дорабатывать, как только определят хранение суммы.
- **Доброска (backfill) декомпозирована**: сначала ветка для **SabyBank**, затем ветка для **обычных сделок**. Инвертировать/добросить с учётом суммы.
- Запрос платформенной команде (Мусохранов) про маркетинговый метод и перестроение агрегатов.

## Обновление 2026-08-06 — сумма реализована, пункт 3 отменён

[[ReferralStub-LeadSum-Implementation]]: задача №08052776 закрывает пункт 3 («пока писать пусто/ноль»).
Поле API названо `LeadSum` — одноимённо колонке `GetPartnerList`. Наполняется тремя путями: `CreateStub`
и `UpdateStub` (присылает вызывающая сторона; для SabyBank — после доработки на их стороне),
`CreateStubsForExistingLeads` (из `ДокументРасширение.Сумма` сделки) и `HandleLeadStateChanged`
(обычные реферальные сделки, у которых на момент создания корешка суммы ещё нет). Место хранения —
ровно то, что решено 23.07: колонка `Сумма` `ВидЦеныДокумент`, `SUM` рядом с `COUNT`.

Открытым остаётся только **доброска уже созданных корешков** — миграция идемпотентна по `OperationId`
и повторный прогон существующие корешки пропускает.

## Обновление 2026-07-31 — количество заявок реализовано, сумма остаётся отложенной

[[ReferralProgram-GetPartnerList-Stub-Stats]]: `GetPartnerList` сдан со статистикой по **количеству** заявок (всех и успешных) на основе корешков — это `COUNT`-часть решения выше. Источник сдачи ([[getpartnerlist-stub-stats-2026-07-31]]) не упоминает поле «Сумма» и не подтверждает его наполнение — по умолчанию считать, что пункт 3 этого решения («пока писать пусто/ноль») всё ещё в силе. Статус страницы остаётся `planned` до явного подтверждения наполнения суммы.
