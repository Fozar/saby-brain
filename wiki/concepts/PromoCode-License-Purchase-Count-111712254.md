# Задача

https://online.sbis.ru/opendoc.html?guid=01a1ea09-33e7-7406-a44e-f9a85d68e1bb&client=3
При сохранении общего промокода на все точки покупка предлагает одну дополнительную точку вместо всех новых.

## Где остановились

18.11.2026: карточка, вложения и полная лента прочитаны; прежних попыток исправления нет. Причина подтверждена серверным логом. Фикс и тесты запушены, MR СБИС создан. Локальный прогон пропущен по решению пользователя; ждём CI.

## Что выяснено по коду

PromoCode.Update вызывает LicenseDispatcher на все точки. В get_sale_point_license_restriction_info наличие хотя бы одной точки в долг подменяет число новых лицензий единицей. Старый helper отдаёт приоритет числу точек без лицензии; расхождение внесено при переносе логики на новый API (ff914eb080).
Сетевой лог из вложения и серверный запрос 34ab1a0f-ce4e-3974-63b4-020491c15e08, 17.11.2026 18:02:56–57 МСК: active=[286], unlicensed=[304,310,317], on_credit=[291,298]. В helper поступили количества 3 и 2, а License.Require получил DISCOUNTS_PS_BALANCE=1; то же количество ушло в конфигурацию баннера. Скриншот подтверждает покупку одной точки за 4000.
В описании две новые точки, но в этом запросе три без лицензии. Причина занижения подтверждена; ожидаемую сумму для конкретного аккаунта нельзя выводить только из описания. Видео не анализировалось.

## Решения и почему

Предложено запрашивать количество точек без лицензии, а единицу оставлять только для проверки существующего долга при отсутствии новых точек. Это возвращает приоритет старого helper и не требует миграции данных. Менять только новый dispatcher и регрессионные тесты; старый helper, биллинг и фронтенд не трогать. Общий dispatcher также используется картами и бонусами — нужны смежные проверки.
