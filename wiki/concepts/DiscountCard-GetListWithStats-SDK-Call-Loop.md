# DiscountCard.GetListWithStats — петля за франшизным балансом

Ошибка на стенде №090810941 (`01a0812e-1c2a-7090-8113-d89608f79dc5`), автор Митин, срок 28.11. Решение предложено в задаче 11.09, Кузаков согласовал 15.09 («+»). Сделано 02.10.2026, ветки `26.6100/bugfix/aatimoshenko/090810941` в обоих репозиториях.

## Что было

Список карт типа во внутренней админке дисконтных карт (inside-зона СДК) зовёт `Card.GetListWithStats/4` в discount-cards. Тот проксирует в online `DiscountCard.GetListWithStats/4`. На франшизном аккаунте online за балансом франшизных карт идёт обратно в СДК: `Card.GetBonusBalanceByCards`. Платформа ловит петлю discount-cards -> ext-registration -> discount-cards, первым в логах падает `Платформа.ФорматМетода/2` (он вызывается перед настоящим методом).

Итоги (`GetListWithStatsTotals`) устроены так же и петлю давали тоже, хотя в задаче её нашли только на списке.

## Решение: фильтр `SkipFranchiseBalance`

**online (price-formation)**, `discountcard/discountcard/get_list_with_stats.py`:
- в список при фильтре добавляется колонка `IsFranchise` (у франшизных `True`, у остальных `False`), баланс франшизных карт пустой, в СДК не ходим;
- в итогах баланс считается только по нефраншизным картам, UUID франшизных отдаются в `CardUUIDList` (без фильтра это поле, как раньше, удаляется);
- при `WithBonuses` франшизные карты без баланса в списке остаются — баланс по ним не получали;
- фильтр описан в `DiscountCard.orx` как `std_parameter` с `filter_category="SOFTWARE"`.

**СДК (discount-cards)**, `dcservice/inside/card/get_list_with_stats(_totals).py`:
- кладёт в фильтр `SkipFranchiseBalance=True`;
- если в ответе есть `IsFranchise` / `CardUUIDList`, досчитывает баланс у себя через `get_bonus_balance_by_cards` (локальная БД), применяет `WithBonuses` и убирает служебные поля из ответа.

**Совместимость в обе стороны.** Старый online фильтр не знает и служебных полей не отдаёт — СДК ничего не досчитывает. Новый online без фильтра работает по-старому. Порядок выката не важен, но петля уходит только когда обновлены обе стороны.

## Попутно исправлено в online

Раньше на франшизном аккаунте условие `has_franchise and is_card_franchise is not None and balance_by_cards` перезаписывало баланс **всем** картам, включая нефраншизные (например, карту без клиента): `balance_by_cards.get(...)` давал `None`. Теперь баланс из СДК подставляется только франшизным картам. Тест `test_franchise_balance_keeps_local_balance`.

## Ревью

- **Sonar `radon-block-metric`**: правка подняла `get_list_with_stats` с C (17) до D (21). Вынесены `_get_franchise_balance` и `_set_franchise_balance`, итог C (14).
- **reviewbot, «WithBonuses после пагинации, страница неполная»** — не новое. На франшизном аккаунте SQL в online по `WithBonuses` не отбирает вообще (`{% iftrue has_franchise %} TRUE`), карты отбрасываются в Python после навигации, и обычные тоже. Итоги при франшизе `WithBonuses` никогда не учитывали. Честный отбор до навигации требует, чтобы online знал баланс франшизных карт — отдельная доработка.
- **reviewbot, «объявить `IsFranchise` и `CardUUIDList` в returns orx»** — сознательно не объявлены. Формат результата строится из orx (`sbis.MethodResultFormat`), поле попало бы в каждый ответ фронту, а `AddColBool` упал бы на дубле. Поля описаны в комментарии к фильтру. Что платформа отдаёт необъявленные поля, видно по `be4e28b115`: служебные списки `Bonus.GetClientListWithStatsTotals` уходили клиенту, и их пришлось убирать явно (вывод, отдельно не проверялся).
- **reviewbot, «`IsFranchise` только `True`, у остальных `null`»** — исправлено, теперь `False`.
- **reviewbot в СДК, «докстринги всё ещё про proxy-метод»** — исправлено в docstring и `Inside.orx`.

**Принцип от Тимошенко:** описание метода не должно знать, кто его зовёт. Формулировку «Запрос из СДК: … СДК посчитает сам» он забраковал — метод описывает возможность исходя из того, что знает про себя («Не получать баланс франшизных карт, вместо него отметить их полем IsFranchise»). Фраза «баланс франшизных карт хранится в СДК» допустима: это метод знает про себя сам.

## Для QA

Нужен аккаунт-владелец франшизы с бонусами: франшизные карты клиентов с ненулевым и нулевым балансом и карта без клиента со своим балансом. Проверить: список карт типа в админке открывается без ошибки, баланс франшизных карт совпадает с «Бонусы -> Клиенты»; итоги в шапке равны сумме по картам; отбор «с бонусами» убирает франшизные карты с нулём; в online-списке карт типа карта без клиента показывает свой баланс; на аккаунте без франшизы всё как раньше. Точное название раздела админки не уточнялось.
