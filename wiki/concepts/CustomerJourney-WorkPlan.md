### Этап 1.1 Триггерные события — детали

Цель: получить триггерные события и действия для последующего использования в маршрутах.

**События (52,5 д)**: Посетитель сайта (брошенная корзина/добавление в корзину/просмотр товара — [[Соков-М]] 2д), анализ действий и генерация триггерных событий (Гайдабура О., Черцов С.), фиксация фактов для трекинга в МП/виджетах SabyGet (Подцепко И., Белов Д., Прищеп А., Погосян Г., Шерчков А.), Клиент\Создание (консультации — Кочетовский А. 0.5д), Карта\Выдана ([[Омельяненко-Егор-Анатольевич]] 1д), Бонусы\Сгорание (Омельяненко Е. 2д + Матюшев Д. 3д), Бонусы\Списаны|Начислены (Матюшев Д. 2.5д), Промокод\Выдан|Использован (Матюшев Д. 2.5д), Осуществлена продажа (Лазаренко А. 7д), Посетитель сайта\Первый/каждый заход (Гайдабура О. 2д). Тестирование — Каретникова М. 3д.

**Действия (23 д)**: пользовательский GUI для параметров действий (Попков П. 4д); «Изменить баланс бонусов / Назначить скидку / Выдать промокод» — БЛ+компоненты ([[Ютман-Элина]] 4д, Марков А. 2д, Матюшев Д. 3д); добавить/удалить клиента из папки (Гаврилов М. 3д); отправить сообщение (Новожилов И. 2д); выполнить СПК-код (Веткин А. 2д, консультации); маппинг данных между событиями и действиями (Матюшев Д. 3д).

**Сценарий сдачи**: через интерфейс триггеров создаются триггеры (на объекты лояльности) на каждое обозначенное событие/действие в различных комбинациях.

### Этап 1.2 Реестр и карточка сценариев — детали

Страница с реестром (26д): мастер с иерархией сценариев (Ютман Э., UI Маршруты — Банникова М., БЛ — Матюшев Д.), `MasterList/4` (2д [[Полевщиков-Евгений]] + 3д Федоров А.), деталь со списком ([[Полевщиков-Евгений]] `DetailList/4`), удаление/перемещение папки-сценария, история изменений, первый вход, регистрация новой категории маршрута «Лояльность» (Полевщиков Е. 2д).

Карточка сценария (34д): методы Create/Read/Update ([[Полевщиков-Евгений]], Чусовитин), вкладки Описание/Этапы/Схема/Проходы (см. [[CustomerJourney-Scenario-Model]] для UI-деталей), виджет со статистикой проходов (Марков А. UI + Голубь БЛ), фильтр отбора триггерных событий по списку объектов (Фадеев Д. 1д).

**Сценарий сдачи**: страница «Скидки → Сценарии»; мастер папок со счётчиками; создание сценария «По событию»; карточка с вкладками Описание/Этапы/Схема/Проходы работоспособна.

### Этап 2.2 Авто-проходчик маршрутов — детали

Крупнейший технический этап (59 дней). Цель: клиент, помещённый на маршрут (с любым числом этапов), автоматически доводится до конечного этапа авто-проходчиком, с «засыпанием» на этапах «Ожидания». API-детали — см. [[CustomerJourney-Route-Service-API]].

> [!tip] Сценарий сдачи (с ограничением по объёму)
> «Все бизнес-сценарии, обозначенные в ТЗ, взлетают. За исключением карточки прохода и глобальной пред-фильтрации» — эти две функции сдаются отдельными этапами (2.3, 2.5).
