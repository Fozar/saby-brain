# Дата создания корешка позже даты сделки, ВНР (№10232921)

## Задача

Ошибка на стенде №10232921, автор Земцова А.В. Ссылка: https://online.sbis.ru/opendoc.html?guid=01a167a0-c60c-7b2a-bfd6-3f400969845e&client=3
Версия online-inside 26.5118, срок 27.10.2026. Стенд fix, портал РС Лидар, «Оффер СО ВСЕМ», корешок Яковлевой Д.С.: дата создания корешка не совпадает с датой создания сделки. ВНР №10233093.

## Где остановились

23.10 собран архив `s_timoshenkoaa_10233093_v1.zip` (в `www/service/Модули/LoyaltyReferral`, вне git). Запрос скрипта проверен на fix (`manual_tests`, схема `_0c1708ed`) только чтением: схема read only. Как ВНР скрипт ещё не запускался. Тестированию переданы три корешка для проверки. Описание ВНР подготовлено по образцу ВНР №09241802 (что затрагивает, результат, повторный запуск безопасен), осталось завести ВНР 10233093 с архивом.

## Что выяснено

- Проблема переходного периода. Сделка создана до того, как корешки стали заводиться в живом режиме, и до ВНР по старым сделкам. Корешок появился позже, при смене статуса сделки (`handle_lead_state_changed` -> `create_stub_by_lead`), а он ставит дату создания на текущий момент. ВНР по старым сделкам эту сделку уже пропустил: корешок по её UUID был.
- Живой код не правим: по решению ревьювера корешок живого режима получает текущее время (см. №09097007).
- Дата создания корешка в реестре и в детализации берётся из колонки `ВидЦеныДокумент.ДатаВремя`. В атрибуте `CreatedAt` хранится то же время строкой в часовом поясе сервиса.
- ВНР по старым сделкам ставил дату создания из `ДокументРасширение.ДатаВремяСоздания`, у его корешков даты совпадают со сделкой до микросекунды.
- В `_0c1708ed` корешков по сделкам 10, расходятся 3: «test [2.0]» заявка 127 (10.08.2026, должно быть 18.06.2026), «Первый оффер × 666» заявка 14 (10.08.2026 -> 17.02.2026), «Оффер СО ВСЕМ» заявка 777 (23.10.2026 -> 28.10.2025). Партнёр у всех «Локатор СПб, ООО», статус «В работе».

## Решения и почему

- Скрипт правит корешки программ с типом `REFERRAL_LEAD`, которые созданы больше чем через час после сделки (корешок, созданный вместе со сделкой, отстаёт на секунды). Связь корешка со сделкой через `OperationId` = `ИдентификаторДокумента`.
- `ДатаВремя` = `ДатаВремяСоздания` сделки, атрибут `CreatedAt` сдвигается на ту же разницу, чтобы не зависеть от часового пояса. Старая дата пишется в лог ВНР для отката.
- Без файлов `*_cloud_clients`: корешки обычных программ лежат в аккаунтах владельцев, скрипт идёт по всем клиентам, как прошлый ВНР по сделкам.

## Открытые вопросы

- Дату статуса (`EffectiveDate`) скрипт не трогает. У заявки 777 статус «В работе», дата статуса тоже на 23.10. Если тестирование это заметит, добавить в скрипт.
