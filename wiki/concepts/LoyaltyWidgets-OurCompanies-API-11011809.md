## Фича: уточнение пользователя

Техническое имя фичи №94256 — `our-org-all-product` (сообщено пользователем в этой сессии).
До реализации нужно согласовать границы обхода иерархии: текущая выборка без H/SH включает выбранную организацию и непосредственных детей, с H/SH — только выбранную. Не менять глубину неявно при переходе на API. Семантика конкретных значений Depth пока не подтверждена.

## Согласованные границы и предлагаемое решение

Пользователь подтвердил: существующее поведение сохраняем. Без H/SH — выбранная организация и непосредственные дети; с H/SH — только выбранная организация.

Предложение на согласование (не разрешение на реализацию): под our-org-all-product заменить два SQL-запроса в _get_available_companies_only вызовами OurOrg.MassiveBranchsList/2. Продуктовую синтетику передавать как ID без собственной трактовки SPType; для конкретной организации ограничить глубину непосредственными детьми и добавить саму организацию. Для H/SH обход не выполнять; -1/-2 и действующие пересечения с правами не менять. Без фичи оставить старый путь. Результат branchs развернуть в список ID. При пустой продуктовой выборке сохранить существующий непустой маркер [org], иначе encode_params снимет отбор. Известную обработку пустого пересечения с правами не расширять в рамках этой замены.

API по умолчанию применяет Visible=True: чтобы не добавить скрытую фильтрацию относительно SQL, предлагается Visible=False, OnlyActive=False, IncludeASP=True. Конкретное числовое значение Depth нужно подтвердить по контракту/платформенному тесту перед написанием реализации: известен сам параметр, но его нумерация не проверена.

Тесты: оба состояния фичи, синтетика -10/-11/-12/-13/-15, пустой ответ API, H/SH, дети и внуки, -1/-2 и существующая обработка прав. Расчёт агрегатов и фронтенд не менять. Техническое решение ожидает одобрения; код не менялся.

## Реализация и проверка контракта

Depth=1 подтверждён исходником contragents/online, rc-26.6100, `bl-modules/OurCompanyBase/sql/branches/massive_branchs.sql`: корень имеет level=0, рекурсивный шаг допускается при level < Depth. Исходник получен read-only через git archive по SSH. Visible=False нужен для сохранения учёта скрытых организаций. IncludeASP=True и OnlyActive=False — значения API по умолчанию.

Под фичей синтетические ID передаются API, branchs разворачиваются в список. Для обычной организации запрашивается один уровень и отдельно сохраняется корень. Пустая продуктовая выборка сохраняет прежний маркер [org]; encode_params не теряет ограничение. Ошибки API не скрываются SQL-fallback. Без фичи старые запросы оставлены.

Добавлены тесты в `tests/tests_loyaltywidgetsonline/widgets/loyaltywidgets/loyalty_widgets_tools.py`, обновлена карта widgets. API в тестовом облаке замокан: прохождение unit-тестов не означает проверки живого API на стенде. Его собственные правила (исключение RegInProgress и черновиков потомков) не дублируются в лояльности.
