# CustomerJourney UI Decomposition («Путь клиента» — интерфейс)

Декомпозиция UI-экранов проекта [[CustomerJourney-Scenarios-Project]]. Все мокапы визуально проверены (см. источник [[customer-journey-tz-2026-07-03]]) — текстовые описания в ТЗ дословно соответствуют скриншотам. Реализуется на компонентах [[Route-Platform-Architecture]] (Route/*), с общими элементами реестра скриптов и чат-ботов.

## Доступ к разделу

На примере Saby Retail: **Скидки → Скидки и акции → Сценарии**.

## Первый вход (пустое состояние)

Приветственный экран «Персональный подход»: создать сценарий с нуля или выбрать один из 4 шаблонов — «Бонусы при регистрации», «Давно не покупали», «День рождения», «Брошенная корзина». Реализуется через платформенный `emptyViewConfig`; определение состояния — новый БЛ-метод по аналогии с `Promotion.HasAvailable` (проверяет, есть ли уже созданные/деактивированные сценарии на аккаунте).

## Экран «Сценарии» (реестр, мастер-деталь)

Двухколоночный реестр: **мастер** (`Route/Registry/master:View`) — иерархия/папки; **деталь** (`Route/Registry/list:View`) — сценарии выбранного пункта иерархии.

- **Левая панель (Навигация)** — фильтр по папкам (напр. «Все», «Начисление бонусов», «Уведомления»)
- **Правая панель (Список)** — каждый пункт: название, счётчик «Клиенты» (попавшие в выборку), счётчик «Прошло» (завершившие маршрут)
- **Верхняя панель (Тулбар)** — кнопка «+», строка поиска, фильтр по периоду (влияет на счётчики)

### Операции над записью

Удаление (для сценариев — массовое), перемещение между папками (для сценариев — массовое), изменение названия (только папки), показать историю (только сценарии).

### Глобальные настройки (шестерёнка)

Боковая панель ограничений попадания клиентов в сценарии:
- **Частота** — «Клиент попадает в сценарий не чаще N дн»
- **Ограничить срабатывание** — тумблер, запрещающий новый сценарий для клиента с незавершённым текущим проходом
- **Режим тишины** — тумблер приостановки срабатывания в промежуток времени (с учётом часового пояса клиента)

(Соответствует платформенным параметрам `no_more_often_term`, `one_user_run_pass`, `silence_mode` — см. [[Route-Platform-Architecture]] §Глобальная предфильтрация.)

### Меню создания сценария (кнопка «+»)

Типы сценария:
- **По событию** — наведение раскрывает иерархию доступных объектов/событий (Лояльность → По дисконтной карте; Клиент → Розничная покупка и т.д.)
- **Периодический** — заданный временной интервал
- **Разовый** — единичный запуск по выбранному списку клиентов

BL-обёртки над методами Route: создание — `RouteService.Create`, удаление — `RouteService.Delete`, перемещение — `RouteService.ChangeFolder`, история — встроенный механизм `RouteService.Update` (специфичных сценариев истории для маршрутов лояльности на момент ТЗ не предполагается).

Загрузка данных реестра — прикладная обёртка над `RouteService.List`; права доступа задаются в обёртке, зона `PF-LoyaltyProgram-PUB`.

## Экран сценария (карточка, вкладки Описание / Этапы / Схема / Проходы / Статистика)

Редактирование страницы — платформенный `formMethodConfig`; чтение/сохранение — прикладные обёртки над `RouteService.Read`/`RouteService.Update`.

### До запуска (вкладка «Описание»)

- **Смена типа сценария** «на лету» (По событию / Периодический / Разовый)
- **Настройка триггеров** (По событию) — панель «События» с иерархическим реестром (Лояльность, Клиент, Посетитель сайта и т.д.)
- **Настройка расписания** (Периодический) — модальное окно «Повторять»: календарь повторений (каждую неделю/раз в месяц/по датам/циклами), выбор дней недели

### После активации (вкладка «Описание» → дашборд)

- Шапка: иконки «Карандаш» (редактирование), Play/Pause (старт/стоп)
- **Виджеты метрик**: Отправлено Email, Начислено бонусов, Прошло сценарий (шт. и %), Выручка
- **График**: соотношение Выручки и количества Покупок по дням; ниже — текстовое описание логики + условия отбора
- Виджет статистики по проходам — прикладной метод-обёртка над `RouteStat.GetGoalStepStat`

Блоки вкладки (все — блоки платформы маршрутов): Описание, **Тип сценария** (реализуется в рамках проекта), Ответственный, **Условия отбора** (реализуется в рамках проекта). Все данные для отображения лежат в корне результата чтения сценария — отдельные методы БЛ не нужны. При маршруте по событию «создание клиента» **обязателен** фильтр тех.триггера по типу клиента (иначе срабатывает на любых контрагентов).

### Вкладка «Этапы»

Альтернативный визуальному редактору вид: левая панель — линейный список блоков маршрута; правая — детальная конфигурация выбранного блока (окно настроек идентично вкладке «Схема»). Компонент: `Route/ScriptPage/Scheme/list/Function/View`, свойства — `Route/ScriptPage/Scheme/list/IViewProps`. Иконка/название/цель отображаются из наличия массива `Targets` в ноде списка. Модель: `Route/Models/Scheme/base/SchemeElementModel`, `Route/Models/Scheme/base/NodeModel`. Известный нюанс: в детейле (в отличие от мастера) отсутствует иконка — требуется доработка.

### Вкладка «Схема»

Drag-and-drop интерфейс построения маршрута. Компонент: `Route/ScriptPage/Scheme/constructor:View`; каждый элемент схемы — виджет (платформенный набор SchemeBase widgets + базовый набор Route widgets, обёртки первого набора). Обязательное условие — общая модель `SchemeElementModel`; отображение виджета определяется полем `EditorType` (путь до элемента схемы).

- **Пустое состояние** — подсказка по базовым блокам: Действие, Условие, Ожидание
- **Добавление узлов** — кнопка «+»: быстрые действия (Начислить бонусы, Назначить скидку, Отправить) или базовые блоки (Действие, Условие, Ожидание)
- **Блок «Действие»** — модальное окно параметров (напр. кол-во бонусов); «+ Действие» группирует несколько действий в одном этапе
- **Блок «Ожидание»** — пауза (напр. «Ждём 10 дней»); ветвление: событие → одна ветка, «Время вышло» → другая (ветка отказа/напоминания); у каждого исхода свой переход

### Вкладка «Проходы»

Компонент: `Route/ScriptPage/Passes/registry:View` (`viewMode: 'custom'`, `masterFilters`, `masterStoreIds`, ...). Мастер (сводка по блокам) — обёртка над `RouteStat.GetStat`; деталь (список клиентов) — обёртка над `RouteService.TraceList`.

- **Сводка по блокам (левая панель)** — агрегированная статистика успехов/отказов по ключевым блокам (напр. сколько отвалилось на «Ожидание», сколько получили Email)
- **Лента событий (правая панель)** — хронологический список клиентов по датам; строка: аватар, ФИО, краткая выжимка пути, статус (успех/отказ), время в сценарии, сумма выручки
- **Детализация прохода (карточка клиента)** — шапка с контактами (ФИО/телефон/email) + вертикальный таймлайн прохода: момент отбора, начисления, этапы ожидания, зафиксированные события («Есть покупка» с товарами/суммой); отображаются и завершённые, и «зависшие» на ожидании проходы
- **Глобальная история клиента** — по стрелке «Назад»: сводный реестр всех сценариев клиента (статус + выручка по каждому)

Компоненты мастера: `Route/ScriptPage/Passes/master:Title` (нужна доработка — обогащение иконкой), `Route/ScriptPage/Passes/master:Counter`. Компоненты детейла: `Route/ScriptPage/Passes/_list/columns:Employee` (доработка — прикладной текст после сотрудника), `Route/ScriptPage/Passes/_list/columns:Stage` (доработка — зелёный цвет покраски). Конфигурация колонок — хук из `Route/ScriptPage/Passes/list`.

## Карточка прохода (отдельная страница)

Реализуется отдельной pagex-страницей с предзагрузкой данных. Источник данных — БЛ-обёртка над `RouteService.FindTrace`: возвращает список пройденных этапов конкретного прохода **и** список всех проходов клиента по маршрутам. Список этапов — `Events` с UUID узлов/переходов (`Node`/`Pass`); человекочитаемые строки формируются клиентом сращением `Events` из `FindTrace` с моделью маршрута из `RouteService.Read`. Метаданные (даты попадания/ухода, данные продажи, ошибки) — тоже в `Events`.

Компоненты декомпозиции: `Person/information:NewView` (шапка контакта), `Controls/grid:View` (список проходов клиента / таймлайн этапов), `Controls/extButtons:ArrowButton` (переход к глобальной истории).

## Вспомогательные компоненты вкладки «Реестр»

```jsx
<Title titleProperty="title" counter={<Counter counterProps="count" />} />
```

Для детейла — массив колонок с компонентами `Title` (`titleProperty`) и `Counter` (`counterProperty`), пример: `{key: 'countClients', render: <Counter counterProperty="count" />, width: 'max-content', getCellProps: () => ({halign: 'right'})}`.

## Известные доработки/несоответствия макета на момент ТЗ

- Вкладка «Описание»: отображение условия отбора и типа сценария должны быть **одним компонентом**, в текущем макете — разделены
- Вкладка «Этапы»/«Проходы»: детейл не имеет иконки (в отличие от мастера) — требуется доработка
- Вкладка «Проходы»: колонка «Сотрудник» нуждается в доработке для добавления прикладного текста; колонка «Stage» — для покраски в зелёный
