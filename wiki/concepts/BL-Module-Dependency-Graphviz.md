# Визуализация зависимостей БЛ-модулей через Graphviz (S3modToGraphviz)

Внутренний инструмент для визуализации зависимостей между БЛ-модулями (и модулями фронта) дистрибутива онлайна SBIS/Saby. Дистрибутив онлайна состоит из множества модулей, описанных [[Wasaby-Module-System|s3mod-файлами]] с явными зависимостями; для крупных модулей число транзитивных зависимостей быстро становится непрозрачным без инструмента визуализации.

## Мотивация

Задача возникла в контексте анализа зависимостей модуля БЛ **Cadres** (кадровый учёт) от модуля **«Зарплата и кадры» (ЗиК)**. Исторически функционал кадрового учёта был частью «Зарплаты и кадров»; впоследствии выделен в отдельный модуль Cadres, но осталось много мест, использующих логику из ЗиК. Планируется (совместно с командой зарплаты) навести порядок: вынести общий функционал в новый более лёгкий модуль **SalaryCore** и заменить зависимость `Cadres → ЗиК` на `Cadres → SalaryCore`. Чтобы оценить масштаб задачи, потребовалось увидеть, какие транзитивные зависимости модуль ЗиК тянет в Cadres — готового внутреннего инструмента для этого не нашлось (возможно, есть у отдела сборки/платформы, но не проверялось), поэтому использован сторонний [Graphviz](https://graphviz.org/).

## Как работает

1. Инструмент разбирает `*.s3mod`-файлы БЛ-модулей дистрибутива онлайна и генерирует описание графа зависимостей в формате Graphviz (текстовый `.gv`-файл: узлы = модули по UUID с `label`, рёбра = зависимости).
2. Установка: `graphviz` (rhel9) + Python-пакет `graphviz`.
3. Запуск с параметрами командной строки:
   - `s3mod_folder` — папка с s3mod-файлами
   - `target_folder` — папка для результата (`.gv`-описание графа)
   - `--specific_module` (опционально) — построить граф начиная с конкретного модуля, а не весь граф целиком
4. Рендеринг картинки из `.gv` — командой Graphviz (`dot`/аналог), формат SVG (удобно увеличивать для больших графов).

Пример фрагмента `.gv`-описания для прямых зависимостей модуля Cadres (14 узлов вида `"<uuid>" [label=<Название>]` + рёбра `"Cadres-uuid" -> "<uuid-зависимости>"`), включая зависимости на EmployeeAttachmentsExt, AnalyticsReportCore, StaffDocs, Python, EKDObjectMapping, "Sync Broker Proxy", EKDCore, «Зарплата и кадры», StaffExtended, EmployeeAccounting, «Бизнес-логика», Staff, «Документооборот», «Документ».

## Уровни детализации графа

- **Прямые зависимости** одного модуля (пример: Cadres) — самый простой граф, ~14 узлов.
- **Все транзитивные зависимости** одного модуля — существенно крупнее.
- **Граф всех зависимостей онлайна** целиком (пример: версия 26.4100) — очень большой, автор иронично комментирует «не для слабонервных».

## Открытый вопрос

Автор не проверял, есть ли аналогичный готовый инструмент у отдела сборки/платформы — возможно, дублирует существующее решение. Прикладного применения за пределами разового анализа зависимостей Cadres/ЗиК источник не описывает; автор явно спрашивает у читателей идеи практического применения.
