# Задача
№10283259: https://dev.saby.ru/opendoc.html?guid=01a1814a-ce95-7770-b296-5828969c8601&client=3
Бой ret.saby.ru, версия 26.5118-135. Веха в полученной карточке не указана.

## Где остановились
28.10.2026: прочитаны карточка, переписка, лента, 3 изображения и sbislogz; запрошены серверные логи. Код не меняли. Пользователь попросил посмотреть ошибку.

## Что выяснено по коду
В клиентском логе Bonus.GetClientListWithStats возвращает 1020 для ClientId 11613, CardId 5366; карточка клиента на изображении показывает 0. Начислено 2000, списано 980; 1020 соответствует остатку до сгорания.
В get_client_list_with_stats.py SQL берёт AvailableBonusBalance из Карта.Атрибуты.Bonus без проверки NextChangeDatetime. Собственный баланс не пересчитывается; отдельно запрашивается франшизная часть.
get_bonus_info_for_client.py по умолчанию рассчитывает актуальный баланс, но UpdateCache=False. Это объясняет возможное расхождение карточки и реестра; фактический запрос карточки в приложенном логе отсутствует.
Обновление кэша предусмотрено в change_handler.py через Action.UPDATE_BONUS_BALANCE. Причина отсутствия обновления после сгорания на конкретной карте не установлена.
Серверный лог запроса 866dfdc3-589d-b9a3-df9e-eddc641315a0 содержит только начало, конец и SQL статистики продаж: состояния кэша нет.
Регрессионные тесты реестра есть в tests/tests_priceformationonline/loyaltyprograms/bonus/get_client_list_with_stats.py.

## Решения и почему
Подтверждён дефект чтения: наш реестр использует сохранённый баланс без проверки актуальности. Не объявлять установленной причиной сбой фонового обработчика или ошибку СДК без данных.
Предварительное направление: учитывать актуальность кэша и пересчитывать устаревшие остатки перед выдачей. Окончательный способ ещё не выбран.

## Открытые вопросы
Нужны атрибуты Bonus и даты актуальности по картам клиента, признак франшизы, история обновления кэша. Apple Wallet упомянут в рекламации, отдельно не проверен.
