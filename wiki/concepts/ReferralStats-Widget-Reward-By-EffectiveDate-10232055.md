# Виджет «Офферы»: вознаграждение по дате создания, а не завершения

## Задача

Ошибка на стенде №10232055, автор Земцова А.В. Ссылка: https://online.sbis.ru/opendoc.html?guid=01a1676c-4721-7ba6-96e2-46a58c6e040e&client=3
Срок 27.10.2026, стенд fix (online-inside 26.5113), портал РС Лидар, виджет «Офферы», фича `ref_deals_convert`. Веха 26.5118 (в карточке не указана, видна в связанных документах).
ФР: вознаграждение = сумма успешных заявок, созданных в месяце. ОР: завершённых в месяце.

## Где остановились
28.10: Земцова вернула с проверки («у партнёра не починилось»), разбор в разделе «Возврат 27.10». Причина не в коде: у партнёра РС Лидар фича `ref_deals_convert` выключена. Ждём решения Тимошенко, как проверять (включить фичу для РС Лидар на fix или проверять на аккаунте с фичей). Состояние кода на 23.10:
Решение согласовано 23.10 (Тимошенко: без фичи не правим, только под фичей; лиды остаются по дате создания). Закоммичено (`926b721b63`), запушено, MR создан 23.10. Ветка `26.5118/bugfix/aatimoshenko/10232055` от `rc-26.5118`. В `sql_get_price_stats` под фичей корешки в `Price` отбираются по `EffectiveDate`, посетители по `ДатаВремя` (условие JOIN и FILTER). Два новых теста (`GetStats`, `GetStatsByPartner`), красные до правки (250 и 270 вместо 350), зелёные после; 22 теста двух файлов OK. В существующем `_regular_program_price` корешку добавлена `effective_date`: по умолчанию в тестовой модели она «сейчас» и выпадала из периода 2023. pylint не гонял (правка внутри SQL-строки).

## Что выяснено по коду
- Виджет — `GetStats` (и `GetStatsByPartner`), вознаграждение считает `sql_get_price_stats` в `get_stats_helpers.py`.
- В `Price` и в условии JOIN строки вознаграждения отбираются по `ptd."ДатаВремя"` (дата создания заявки). Успешные заявки (`PositiveLeadCount`) в том же запросе уже идут по `EffectiveDate`.
- `GetLeadPeriodList` и `GetPartnerList` считают вознаграждение корешков по `EffectiveDate`. Расхождение виджета с ними уже отмечалось в [[ReferralStub-Partial-Indexes]] (замечание reviewbot, п.4), тогда в задачу не входило.
- Индекс `BonusesEffectiveDate` (ВидЦены, EffectiveDate, PK, `Бонусы IS NOT NULL`) под такой отбор есть.

## Решения и почему
Корешки в вознаграждении по `EffectiveDate`, как в `GetPartnerList` и `GetLeadPeriodList`; вознаграждение за посетителей по `ДатаВремя`; `LeadCount` по дате создания (так и должно быть). Без фичи не трогаем. Побочное: у агрегатов с `ТипСвязи` 2/3/5 `EffectiveDate` пустой, под фичей они в `Price` не попадают (в `GetPartnerList` так же). SabyBank без фичи по-прежнему по `ДатаВремя`.

## Ревью reviewbot (23.10, !152859)
1. Medium, принято: `filter_and_sort_stats` убирал строки без заявок и посетителей, хотя вознаграждение в них есть (заявка создана в прошлом периоде, завершена в этом), а в итогах оно оставалось. Под фичей теперь строка с `Price > 0` остаётся. Без фичи фильтр прежний: там заявки идут из маркетинга и `Price` от них не зависит. Тест `test_row_with_price_only_is_kept_under_feature` (красный без правки). В хелпер теста добавлен `with_visitors`.
2. Medium, ждёт решения Тимошенко: `get_list.py` (список программ) считает вознаграждение по `ДатаВремя` и под фичей. Расходится с виджетом. Задача про виджет, список не трогали.
3. Low, не делаем: правило даты записано в FILTER (CASE) и в ON (OR-ветки, чтобы работал индекс по `EffectiveDate`). Привести к одной форме без замера на базе нельзя. Вместо этого в обоих местах комментарий «править вместе».
Правки пока не закоммичены (ждут «ок»), потом amend + force-with-lease во все ветки вехи.

## Возврат 27.10: у партнёра не починилось
Земцова вернула с проверки: у владельца виджет верный, у партнёра (портал РС Лидар, fix-partners) прежний. Веху сняли (просьба Земцовой 27.10, Фомичева вынесла из 26.5118).
По серверному логу вызова `ReferralProgram.GetStats` (fix, сборка 26.5118-130, 27.10 18:32 МСК): запрос статистики ушёл с `IsStubMode = false`, то есть фича `ref_deals_convert` для этой сессии выключена. Внутри был вызов CRM (`SalesSources.ReadStat`), то есть счётчики заявок из маркетинга, а не из корешков. Ответ: «test [2.0]» 400, «№777» 300, «Оффер СО ВСЕМ» без вознаграждения и 9 заявок; в базе владельца `_0c1708ed` по 19 и 58 за октябрь строк нет. Фича проверяется по клиенту и пользователю сессии (`check_feature`), а портал РС Лидар работает на другой схеме (`_00ca2e3b`, `fix-osr-db26`), чем та, где мы включали фичу.
Вывод: правка под фичей работает, у партнёра РС Лидар фича не включена. Это не ошибка кода. Не проверено: сам флаг в админке фич (доступа нет), базы дали таймаут.
Нужно решение: включить `ref_deals_convert` для клиента РС Лидар (13250107) на fix или проверять на аккаунте, где она включена.
