## Что выяснено по коду

- Найдено одно рабочее фронтовое место вызова; поиск по rc-26.6100 других рабочих вызовов не показал.
- Преобразователь композитных ключей возвращает [] для None: значение «все точки» нужно сохранять до преобразования.
- Новый диспетчер возвращает массивы INT64, публичный ответ метода — INT4[]. Локально сохранён прежний формат ответа.
- В смешанном списке точек без лицензии и с лицензией в долг диспетчер запрашивает одну дополнительную лицензию,
  в отличие от старого helper. Пользователь явно запретил менять сам LicenseDispatcher.

## Решения и почему

- По уточнению Матюшева: Options.LicenseType, не License из первоначального описания.
- Сигнатура меняется без перегрузки. Только проверка, без списания лицензий.
- DISCOUNT_PS → BasicLicense, LOYALTY_BONUS → ProLicense, LOYALTY_REFERAL → MaxLicense.
- LOYALTY_INTEGRATION исключён пользователем. Неизвестные и отсутствующие типы отклоняются.
- None — все точки; [] и неразрешённые ключи — положительный пустой ответ, без проверки всего аккаунта.
- Прежние типы массивов и Reason=None сохранены без изменения общего DTO.
- «Оформить MR к задаче» означает документ СБИС через sbis_create_merge_request, а не ручной GitLab MR.
  Первоначально ошибочно созданный !154600 закрыт; правила добавлены в bug и task-to-dev.
