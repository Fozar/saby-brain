# ReferralProgram — UI истории изменений (офферы/лиды/корешки)

Постановка задачи по двум звонкам 2026-07-29 (Тимошенко/Свешников 11:53, затем + Михель Витольд 12:32) — источники [[zvonok-tim-sveshnikov-referral-history-buttons-2026-07-29]] и [[zvonok-tim-sveshnikov-mihel-referral-history-ui-2026-07-29]].

## Текущее состояние (до задачи)

- В реестре офферов при проваливании в конкретную программу — уже видна история изменений программы (название/описание) + история лидов по ней.
- Записи истории по корешкам сейчас пишутся в общую историю реф. программы, отдельной истории по корешку нет.
- История «сыпется со всех рефпрограмм» — не отфильтрована по конкретной программе; статус (баг/ожидаемое поведение) не подтверждён, требует проверки.

## Решение

| Место | Кнопка истории | Что показывает |
|---|---|---|
| Карточка/ховер корешка | Своя, для конкретного корешка | Изменения по конкретной заявке/корешку |
| Страница/карточка оффера | Своя, для оффера (существующее поведение не трогаем) | Изменения названия/описания оффера + создание корешков |
| Общая (по всем офферам) | Существующая, без изменений | Изменения по всем офферам |

**Явно отвергнуто**: объединение в одну общую историю с одновременным показом по офферу и по корешку — «двумя историями точно нельзя» (Свешников).

**Опционально, не решено окончательно**: единый сгруппированный по корешкам реестр с возможностью развернуть — по аналогии с ожидаемым (но, по словам Витольда, не подтверждённым на практике) поведением истории дисконтных карт. Если технически нельзя — остаётся текущий путь «через клик по конкретному корешку».

## Открытые вопросы

- Кто и когда зафиксировал требование «иерархия против ЕСНР» по истории — не восстановлено в звонке, участники сами не были уверены («блин, ну, спроси, я не помню»).
- Реализация группировки с разворачиванием в похожем месте (дисконтные карты) — по словам Витольда ожидалась, по факту список плоский; требует отдельной проверки в коде, не в этой постановке.
