# SabyGet: в виджете партнёра нет приветственных бонусов владельца

## Задача

Ошибка на стенде №110512550, GUID 01a1abd7-5416-7473-8d63-0b46d724f232.
https://dev.saby.ru/opendoc.html?guid=01a1abd7-5416-7473-8d63-0b46d724f232&client=3
Веха 26.6100 sabyget-service, срок 28.11.2026. Передана Тимошенко 13.11 с указанием LoyaltyProgram.GetDescriptionBySalePoint/3.

## Где остановились

18.11 по просьбе пользователя реализация отложена в stash в обоих репозиториях. Коммитов, push и MR нет. Техрешение подготовлено для задачи. Серверные логи перехода протухли, исходный sbislogz сохранил ответ метода.

## Что выяснено по коду

- На странице test.sabyget.ru/shop/omega_stroy_ooo_51 показано «Кешбэк до 10%», в открытом окне присоединения уже есть 200 Б за регистрацию. У владельца ksr_ooo_51 текст включает 200 Б в подарок.
- В исходном sbislogz ответ Establishment.BonusDetails для Омега Строй (EstUUID 13a91fec-24aa-42ab-91bc-5fe92f57d1db, SalePoint 255, ByReferee=false) содержит GreetingValue=200, GreetingBonuses=200, но BonusDescription="Кешбэк до 10%". Это не потеря суммы во фронте.
- price-formation get_description_by_sale_point_v2.py собирает Description и GreetingValue одновременно из настроек текущего аккаунта. _get_description добавляет приветственные бонусы при наличии ровно одного вида выгоды (скидка либо кешбэк).
- СДК get_description_by_sale_point.py получает готовое описание партнёра и затем заменяет только GreetingValue суммой владельца. Description не пересчитывается. Даже актуальная правка №11058821 (97c269b9d) оставляет это расхождение.
- Тесты СДК проверяют GreetingValue, но не соответствие Description новой сумме. Проверены ветки одной линейки 26.6100, без переключения и изменений.
- Граница причины: последующее обогащение ответа в discount-cards; в price-formation нет подмены суммы после формирования текста. Прямой серверный вызов СДК в этом запросе из клиентского лога не виден; его имя указано в переходе Никитина, поведение совпадает с проверенным кодом СДК.

## Решения и почему

Не исправлять фронт строковой подстановкой: серверный ответ уже содержит противоречие. Нужна согласованность готового описания и суммы после выбора бонусов владельца. Конкретный способ пересборки текста ещё не выбран; важно сохранить правила локализации и условия показа выгод.

## Открытые вопросы

- Согласовать работу в discount-cards с Кузаковым.
- Перед реализацией выбрать, как переиспользовать форматирование без копирования правил и разбора готовой строки.
- После исправления проверить ненулевую/нулевую сумму владельца, собственную сумму партнёра, точку вне договора и неизменность реферального входа.

## 18.11: Черновик реализации отложен

- В price-formation добавлена отдельная перегрузка online LoyaltyProgram.GetDescriptionBySalePointV2(SalePointID, ByReferee, GreetingValue). Старые сигнатуры с одним и двумя параметрами сохранены. При заданной сумме она участвует и в GreetingValue, и в Description; None оставляет прежний выбор, 0 является явной суммой.
- В discount-cards метод LoyaltyProgram.GetDescriptionBySalePoint(ClientID, SalePoint, ByReferee) для договорной точки и нереферального входа сначала читает сумму владельца, затем вызывает новую перегрузку online. Внешний вызов со стороны SabyGet не меняется. Убрана последующая подмена только GreetingValue.
- Поставка: сначала online с новой сигнатурой, затем СДК. До согласования не поставлять. Реферальный вход, точки вне договора и обработка недоступности настроек остаются по прежнему пути.
- Проверки до откладывания: online 19 тестов OK на SDK 266100; из них 3 проверки неверной суммы были красными после добавления сигнатуры без изменения выбора суммы. СДК целевой файл прошёл после исправления; после этого добавлена ещё проверка нуля владельца при ByReferee=None, она пока не запускалась. Общие suite не запускались. Ревью и pylint не завершены.
- Обе рабочие папки на ветке 26.6100/bugfix/aatimoshenko/110512550, созданной от origin/rc-26.6100. Ветки не запушены и не содержат коммитов фикса — сама работа находится только в stash.
