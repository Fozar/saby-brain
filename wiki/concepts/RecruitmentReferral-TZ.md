# ТЗ — Реферальная система в подборе персонала

Navigation: [[RecruitmentReferral-Project]] | [[RecruitmentReferral-WorkPlan]] | [[ReferralProgram-Module]] | [[SabyBank-RKO-TZ]]

Полное техническое задание (редакция 13 июл 2026). Обзор проекта — [[RecruitmentReferral-Project]].

Источник ТЗ: `online.sbis.ru/shared/disk/5f4694a9-b830-4420-8973-9a455fbd7b01`. Макеты: [Axure recruitment](https://axure.tensor.ru/recruitment/) (настройка программы, вкладка «Приведи друга», статистика — «готовим к согласованию»).

## 6.1 Архитектура данных

### 6.1.1 SabyNet-конфигурация «Карьера»

Новый тип SabyNet-конфигурации «Карьера» как обычное приложение с родительским приложением `sabynet`, тип **«Партнёрская сеть»**, две конфигурации — **Владелец** и **Участник**.

- Главная страница «Программы» — на `pagex`, тип `custom`.
- Общий для всех страниц офферов компонент с графической шапкой — платформенный `Layout/FlexHeader` (v26.1200).
- Страницы (пустые заглушки на этом этапе): **«Программы», «Отклики», «Посетители», «Партнёры»** (последняя — только в конфигурации Владельца).

> [!note] Наименование конфигурации
> ТЗ называет тип «Карьера», [[RecruitmentReferral-WorkPlan]] — «Вакансии». Расхождение не разрешено.

### 6.1.2 Панель настройки реферальной программы

Дорабатываемые методы:

| Метод | Доработка |
|-------|-----------|
| `ReferralProgram.Create` | Новое поле «Тип рефпрограммы» = «Реферальная программа подбора персонала» |
| `ReferralProgram.Read` | Новые поля «Награда за этап» и «Категория вакансии» |
| `ReferralProgram.Update` | Сохранение «Награда за этап» и «Категория вакансии» (хранится в атрибутах `ВидЦены`) |

Карточка `LoyaltyOnline/ReferralLeadNew/Owner/form:View` для нового типа **скрывает** лишние компоненты: описание вознаграждения, вознаграждение «За лид»/«За посетителя», тему отношений, выбор партнёров, форму обратной связи.

Компоненты панели:
- выбор условий получения вознаграждения — платформенный дропдаун;
- задание вознаграждения — стандартное поле ввода суммы;
- выбор категории вакансии — публичный `HumanResources/categoryOpener/CategoryOpener` (v26.1200);
- выбор компании — `Addressee/field:Input` (как в карточке создания заявки в сделках).

> [!gap] Связь рефералки и вакансии не согласована
> «Категория вакансии (хранится в атрибутах `ВидЦены`) — пока концепт не согласовали, не понятно как будет реализована связь между рефералкой и вакансией».

### 6.1.3 Страница «Приведи друга» для администратора в SabyHRM

- `ReferralProgram.GetList` — в фильтр добавить тип программы. Если не задан идентификатор группы (вызов не в SabyNet) — метод возвращает программы **по всем реферальным сетям** с заданным типом.
- Кнопка создания открывает панель выбора вакансии (публичный компонент), затем — доработанную панель создания программы (§6.1.2).
- Список программ — доработка `LoyaltyOnline/ReferralLeadNew/registry:View`: показать тип и условие получения вознаграждения.

### 6.1.4 Страницы с информацией по реф. программе

**Схема получения данных «Описание»:** по пользователю → `@Лицо` Сотрудника → `Карта.Лицо` (персональная Карта) → по `@ВидЦены` + `@Карта` отбираем `ВидЦеныДокумент` (корешки за N месяцев). Группировка по месяцу (`ВидЦеныДокумент.ДатаВремя` = время создания корешка) даёт количество заявок; сумма `Бонусы > 0` — сумму выплат.

- `ReferralProgram.GetLeadPeriodList` дорабатывается: добавить **количество откликов**.
- UI на базе `LoyaltyOnline/ReferralLeadNew/master:View`; новая колонка «Отклики» в списке периодов; кнопка отправки отклика; для «Кто порекомендовал» — `Addressee/field:Input`.

**Страница «Отклики»** — по корешкам за период, сортировка по дате создания. Для каждого корешка из `ВидЦеныДокумент.Атрибуты` извлекается статус заявки, дата/время, ссылка на фото (либо на лету по ключу связи с документом «Кандидат на вакансию»).

**Страницы «Партнёры» и «Посетители»** — на том же `master:View`.

> [!gap] Кто такие «Партнёры»
> «Участники — это все сотрудники, партнёром они становятся при создании отклика? Т.е. показываем тех, у кого есть данные в корешках?» — не разрешено.

### 6.1.5 Страница «Приведи друга» на карьерном сайте

Новая страница в конструкторе карьерного сайта; новый виджет-список рефпрограмм (неудаляемый в шаблоне); плитка — существующий компонент реестра «Офферы».

### 6.1.6 Виджет «Приведи друга» (SabyMy)

Новый виджет дашборда с неизменяемым описанием «Вознаграждение за рекомендацию сотрудника»; клик → реестр реф. программ. Новый метод предзагрузки возвращает ссылку на разводящую страницу реф. программ в SabyNet; если ссылки нет — пустое представление.

## 6.3 API

### 6.3.2 Новые методы

#### Получить реферальную ссылку — 1д
- **Вход**: `ID_Публикации` или (`Компания`, `Категория`, `ID_Вакансии`); `ID_Сотрудника` (если не из контекста).
- **Алгоритм**: определить программу по компании/категории → проверить участие сотрудника → создать карту участника при отсутствии → сформировать реф. ссылку.

#### Создать корешок кандидата — 1д
- **Сущности связи**: реф. программа, карта участника, документ «Кандидат на вакансию».
- **Вход**: `ID_РефПрограммы`, `ID_ДокументаКандидата`, `RefCode`, `Meta` (дата создания, текущая стадия, публикация).
- **Алгоритм**: по `RefCode` → карта участника; проверить отсутствие корешка по `ID_ДокументаКандидата`; создать `ВидЦеныДокумент`; сохранить метаданные.
- **Ограничения**: повтор с тем же `ID_ДокументаКандидата` недопустим; **уникальный индекс `(ID_РефПрограммы, ID_ДокументаКандидата)`**.

#### Обновить корешок кандидата — 1д
- **Вход**: `ID_ДокументаКандидата`, `НоваяСтадия`, `Итог`, `ДатаИзменения`.
- **Алгоритм**: найти корешок → обновить метаданные → проверить условие программы → если выполнено: создать документ вознаграждения + зафиксировать начисление в `ВидЦеныДокумент`.

#### Статистика участника — 1.5д
- **Вход**: `ID_РефПрограммы`, `Период`.
- **Возврат**: кол-во переходов, откликов, успешных кандидатов, сумма начислений, помесячная агрегация.
- **Источники**: визиты — агрегаты маркетинга; кандидаты — корешки (`ВидЦеныДокумент`); начисления — движение бонусов.

#### Статистика программы — 1.5д
- **Возврат**: кол-во участников, кандидатов, успешных рекомендаций, общая сумма начислений, агрегация по участникам.
