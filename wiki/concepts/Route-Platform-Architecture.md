# Route Platform Architecture (Платформа Маршрутов)

Общая (не только для лояльности — используется ботами/скриптами телефонии) платформенная подсистема Saby, реализующая маршруты (Route) — последовательности этапов, по которым автоматически проходит клиент/сущность. Проект [[CustomerJourney-Scenarios-Project]] добавляет новый тип маршрута `Category=Loyalty` поверх этой платформы. Источник: [[customer-journey-tz-2026-07-03]]. Владельцы: [[Окладников-Д]], [[Чусовитин-А]].

> [!contradiction] Расхождение имён методов с плановым документом
> [[CustomerJourney-Route-Service-API]] (построена на `План работ по проекту.pdf` — плановом, более раннем документе того же проекта) называет методы авто-проходчика `AutoTrace.Start/3`, `AutoTrace.Run/3`, `AutoTrace.OnEvent/3`. Финальное **согласованное** ТЗ (эта страница) фиксирует другие имена: `RouteService.StartTrace`, `RouteService.StartClientRoute`, `RouteService.OnEvent`. Похоже на переименование методов между стадией планирования и финальным ТЗ — не подтверждено текстом источников, требует сверки при ингесте `Концептуальное решение*.pdf`. Также вероятный дубль сущности: [[Чусовитин-А]] (эта страница) ≈ [[Чусовитин-Александр]] (тот же проект, из плана работ, «ответственный за авто-проходчик и постановку на маршрут») — не объединено, требует ручной проверки.

## Ключевые термины

- **Проход (Trace)** — фиксация прохождения клиента по маршруту: клиент, маршрут, время начала/окончания, время попадания/ухода с каждого этапа, доп. данные
- **Переход (Pass)** — факт перемещения клиента по маршруту от этапа куда-либо (другой этап, завершение, внешний маршрут)
- **Авто-проходчик** — серверный робот, автоматически двигающий клиента по маршруту

## Запуск прохода маршрута — 3 режима

| StartType | Название | Инициатор |
|---|---|---|
| 0 | Разовый | Пользователь/внешний сервис, конкретный список клиентов |
| 1 | По событию | Триггер (Сервис Триггеров) |
| 2 | По таймеру (плановые события) | Сервис расписаний |

### Общий набор операций (все 3 режима)

1. Вызывается клиентский метод `Route.StartTrace/2`; вычитываются глобальные переменные фильтрации.
2. Сервис Маршрутов обращается к Сервису выборок: `CoreV3.StartSelection/4(ID выборки, Callback, Placeholder, CallBackError)`.
3. Сервис выборок запускает асинхронную задачу отбора клиентов по выборке.
4. По завершении отбора Сервис выборок пачками клиентов запускает через **DWC** задачу `RouteService.StartTrace(Route, Clients, Placeholder)`.

### Разовый запуск

Пользователь/внешний сервис передаёт ID маршрута → общий набор операций → возвращается статус запуска.

### Запуск по внешнему событию (триггер)

При настройке сценария создаётся скрытый неактивный триггер (существует, пока сценарий не удалён). При активации сценария триггер запускается. Изменение условий срабатывания в интерфейсе = редактирование этого триггера. Если триггер настроен на конкретного клиента — передаёт лицо в `Route.StartTrace/2`; если на всех клиентов — второй параметр `Null`, маршрут запускается для всей выборки. Прикладные сервисы **не связаны напрямую** с триггерами Сервиса Маршрутов — управление идёт по UUID маршрута через методы Route.*.

### Запуск по таймеру

Сервис плановых событий (Сервис расписаний) отслеживает настройки таймеров; при наступлении времени инициирует запуск маршрута в клиентский модуль Маршрутов. Для каждой пачки клиентов (**1000 клиентов**) запускаются сценарии авто-проходчика на **DWC**.

## Правила Сервиса выборок

Новые параметры выборки:
- **Отложенный запуск** — сохраняется в сервисе, запуск по идентификатору методом `StartSelection` (после `SaveSelection`)
- **Одноразовая выборка** — запускается один раз при сохранении
- **Callback для ошибок** — обработка прерванного/неуспешного отбора

Новый метод проверки вхождения: `EntityIds[]` (вектор ID) + `TaskID` (ID выборки) → рекордсет прошедших ID.

## Авто-проходчик маршрутов

Авто-проходчик **не работает постоянно** — запускается по одному из 3 триггеров (ручной/событие/расписание) и прогоняет проход **до упора**: до блока-ожидания или до завершения маршрута.

На каждом этапе:
1. **Выполняет действие** — список действий узла (запуск триггерных действий: «начислить бонусы», «отправить рассылку» и т.д.)
2. **Фиксирует переход** — запись события в `Trace.TraceData.Events`: узел, ребро, время, достигнутые цели, результат
3. **Завершает проход** — если узел типа `2` (точка выхода) или узел `type=8`, или нет доступного ребра
4. **Публикует событие движения этапа** (before/after) — для прикладной логики

### Запуск авто-проходчика

`RouteService.StartTrace` → формируется DWC-сценарий (по одной задаче на клиента) → DWC вызывает `RouteService.StartClientRoute` на сервисе маршрутов для каждой задачи.

### Модель события перехода (Events)

| Поле | Значение |
|---|---|
| Uuid | ID события |
| Begin / End | момент входа / выхода узла |
| Node | UUID текущего узла |
| Pass | UUID выбранного ребра (`Null` для финального узла) |
| Targets | достигнутые цели |
| Result | 0 — нейтральный, 1 — положительный, 2 — отрицательный |
| StepNumber | инкрементальный номер шага |
| Error | bool, признак ошибки |

Данные уходят в `TraceCounter` → основа для статистики переходов (существующими средствами платформы).

### Исполнение этапа «Действие»

Модель узла: `Action` (Uuid действия, передаётся в `Data.TriggerID`).

1. При входе: `Trigger.Notify/4(Action, Declaration, None, None)`
2. Сервис Маршрутов получает `RouteService.OnEvent("Action", Person, Payload)`
3. Фиксация этапа «Действие» в `Trace.TraceData.Events`, переход на следующий шаг, фиксация статистики

### Исполнение этапа «Ожидание»

Приостанавливает движение на заданное время (через сервис расписаний `task-scheduler`), ожидая истечения таймера ИЛИ настроенного события. Реализуется в рамках проекта **«Таймер внутри маршрута»**.

Модель узла:

| Поле | Тип | Описание |
|---|---|---|
| Timeout | Int | дней/часов ждать; `null` — таймер не устанавливается |
| TimeoutPassId | Uuid | ребро выхода при истечении таймера |
| WaitEvents | Array[Json] | список событий выхода |
| WaitEvents[].EventType | String | тип события из справочника |
| WaitEvents[].PassId | Uuid | ребро выхода при событии |
| WaitPassId | Uuid | общее ребро при выполнении всех условий |

Заход в этап: если настроен таймер → `AddTask(queue_time, key, RouteService.OnEvent, RouteService, Client, call_params)` в сервис расписаний; фиксация этапа «Ожидание», проход переходит в состояние ожидания.

Срабатывание таймера: `RouteService.OnEvent("Timer", Person, Payload)` → продолжение по следующему этапу.

Внешнее событие: `RouteService.OnEvent("Action", Person, Payload)` → обработчик считывает карточку маршрута/прохода, обновляет этап «Ожидание»; либо снова ожидание (не все условия выполнены), либо переход дальше.

### Подпроходы

«Подпроход» — совокупность переходов в рамках одного экземпляра маршрута; может останавливаться при выходе в модуль/подпрограмму и возобновляться при возврате по точке выхода. Для сложных маршрутов предусмотрен «Этап подпроход» — вложенный проход внутри основного.

## Sequence-диаграммы (из ТЗ, воспроизведены текстово)

### Схема запуска прохода (участники: Пользователь/сервис, Сервис Триггеров, Сервис расписаний, Сервис Маршрутов, Прочий сервис, Сервис выборок, DWC)

```
alt Разовый старт
  A ->> D: Route.StartTrace(Route)
  D ->> H: CoreV3.StartSelection/4(ID выборки, Callback, Placeholder, CallBackError)
  H ->> D: Статус о запуске
  H -->> F: Route.StartTrace(Route, Clients, Placeholder)   [пачками через DWC]
  D -->> A: Статус о запуске прохода
else Старт по событию
  E ->> B: событие, на которое настроен триггер/таймер
  B ->> D: Route.StartTrace(Route, clients or Null)
  D ->> H: CoreV3.StartSelection/4(...)
  H ->> D: Статус о запуске сбора клиентов
  D -->> B: Статус о запуске прохода
  H -->> F: Route.StartTrace(Route, Clients, Placeholder)
else Старт по таймеру
  C ->> C: Срабатывает условие таймера
  C ->> D: Route.StartTrace(Route)
  D ->> H: CoreV3.StartSelection/4(...)
  H ->> D: Статус о запуске сбора клиентов
  D -->> C: Статус о запуске прохода
  H -->> F: Route.StartTrace(Route, Clients, Placeholder)
end
```

### Схема авто-проходчика (участники: те же + Статистика проходов G)

```
F ->> D: Запуск прохода по маршруту
D -->> E: Публикация события о начале прохода (route_service.start_trace)
D ->> D: Создание прохода; фиксация этапа "Начало"
loop по всему маршруту
  alt Этап действие
    D -->> B: Trigger.Notify/4(Action, Declaration, None, None)
    D ->> F: Переходим в ожидание
    B ->> D: RouteService.OnEvent("Action", Person, Payload)
    D ->> D: Фиксация этапа "Действие", переход на следующий шаг
    D -->> G: Фиксация статистики
  else Этап ожидание
    alt установлен таймер
      D ->> C: AddTask(queue_time, key, RouteService.OnEvent, ...)
      D -->> B: Trigger.Notify/4(Action, Declaration, None, None)  [поджигаем ожидание событий]
      D ->> D: Фиксация этапа "Ожидание"
      D -->> G: Фиксация статистики
      D ->> F: Переходим в ожидание
    else Сработала активация
      alt По таймеру
        C ->> D: RouteService.OnEvent("Timer", Person, Payload)
      else По событиям
        B ->> D: RouteService.OnEvent("Event", Person, Payload)
        D ->> D: Обновляем этап "Ожидание" случившимся событием
        alt Не все условия случились
          D ->> F: Переходим в ожидание
        end
      end
      D ->> D: Обновление этапа "Ожидание"
      D -->> G: Фиксация статистики
      D ->> D: переход на следующий этап
    end
  end
end
```

## API маршрута (новое)

| Метод | Назначение | Логика по типу |
|---|---|---|
| `Route.Start(RouteUUID)` | Запуск сценария | Разовый → `Route.StartTrace`; По событию → `Trigger.Create`; По расписанию → C++ `AddTask` |
| `Route.Stop(RouteUUID)` | Остановка сценария | Разовый → `CoreV3.Cancel/1`; По событию → `Trigger.Delete`; По расписанию → C++ `RemoveTask` |
| `Route.Status(RouteUUID)` | Статус сценария | `CoreV3.ReadSelection/1.ClientCount` = найдено; состояния ниже |
| `Route.StartTrace(RouteUUID, Params)` | Постановка на авто-прохождение | Решение о запуске через выборку или напрямую в DWC (если переданы конкретные клиенты и выборка не настроена) |
| `RouteService.StartTrace` | Запуск авто-прохода прикладными разработчиками | Входные: `Route`(uuid), `Client`(int64), `Persons`(int64[]), `Params`(Record: `Version`, `Redaction`, `Reason` 0/1/2, `EventType`) |
| `RouteService.OnEvent` (событие) | Вызывается триггером при наступлении события | `Route`, `Client`, `Payload`(json) |
| `RouteService.OnEvent` (таймер) | Вызывается сервисом расписаний по завершении таймера | `Route`, `Client` |

### Состояния сценария

`draft` (настроен, не запущен) → `starting` → `running` → `stopping` → `stopped`; `error` — ошибка запуска/выполнения.

### Ограничения `Route.StartTrace`

- Если не переданы клиенты и не настроена выборка → авто-проходчик не может быть запущен
- При `Category.silence_mode = True` — запуск маршрутов по категории не производится

## Модель хранения (Route / Trace)

Таблица `Route`: `StartType` (Int: 0 разовый / 1 по событию / 2 по таймеру), `StartMode` (Record). `StartMode`: `Type`, `Filter` (int, ID выборки), `FilterType` (0 — Клиенты), `Trigger` (UUID триггера запуска), `PeriodicityData` (Record параметров планового события).

Регистрация в `Route`: `Category=Loyalty`. Регистрация в `Registry`: `manual`/`event`/`planed`. Регистрация в `Trace`: `pass_type=6` (маршруты лояльности).

## Глобальная предфильтрация клиентов

Через сервис глобальных переменных, платформа вводит параметры (формат `Category.Name`, напр. `Loyalty.silence_mode = true`):

| Параметр | Тип | Описание | Проверка |
|---|---|---|---|
| `silence_mode` | bool | Режим тишины — новые маршруты не запускаются | `Route.StartTrace/2` |
| `one_user_run_pass` | bool | Одновременно только 1 запущенный маршрут на лицо | клиентский `Route.StartTrace/2` (конкретный клиент) + `RouteService.StartTrace/3` (клиент из выборки) |
| `no_more_often_term` | record (`term`: int, `type`: 0-дни/1-часы) | Запускать не чаще N дней/часов | `RouteService.StartTrace/3` |

Панель глобальных настроек — отдельная pagex-страница; методы БЛ: `LoyaltyRoute.ReadSettings`, `LoyaltyRoute.UpdateSettings`.

## Метрики продажи в карточке прохода (детализация)

Прикладное событие во время авто-прохода может вернуть данные метрик, фиксируемые на событие для последующей агрегации на маршрут (например: сколько заработали с продаж, напомнив о брошенной корзине).

```json
{
  "metrics": [
    {
      "Type": "purchase",
      "Key": "abc-123",
      "Amount": 1500.00,
      "Currency": "RUB",
      "OccurredAt": "2026-04-14T10:00:00Z",
      "OptionalData": {}
    }
  ]
}
```

Записывается в прикладное поле `Trace.TraceData.Events.Metrics`. **Без возможности агрегации по сумме покупок в текущем проекте** (см. [[CustomerJourney-Scenarios-Project]]) — только фиксация на конкретном событии/проходе.

## Схема взаимодействия сервисов (6.2)

```
Сервис Online -> Сервис Триггеров        : Генерация триггерного события
Сервис Триггеров -> Сервис Online        : Выполнение действия, определённого в триггере
Сервис Выборок -> Сервис Online          : Отбор Клиентов
Сервис Выборок -> Сервис Маршрутов       : Отправка множества отобранных Клиентов
Сервис Маршрутов -> Сервис Расписаний    : Постановка таймера
Сервис Расписаний -> Сервис Маршрутов    : Вызов callback поставленного таймера
Сервис Триггеров -> Сервис Маршрутов     : Инициализация обработки добавления клиента на маршрут / пробуждение с "Ожидания"
```

Для асинхронного взаимодействия между сервисами используется **DWC** — см. [[DWC-Distributed-Workflow-Coordinator]].
