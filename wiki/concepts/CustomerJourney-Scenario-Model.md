# Путь клиента — понятийная модель сценария

Navigation: [[CustomerJourney-Loyalty-Scenarios-Project]] | [[domains/price-formation/_index]]

Понятийная модель («Концептуальное решение 2») и типы блоков схемы («Блоки для сценариев лояльности»), которыми оперирует конструктор сценариев проекта «Путь клиента». Модель спроектирована по образцу конкурента [[Mindbox]] (с оглядкой на [[REES46]]).

## Ключевые понятия

| Понятие | Определение |
|---|---|
| **Сценарий** | Совокупность блоков, позволяющая пользователю настроить автоматизацию действий, направленную на привлечение клиентов и увеличение их лояльности |
| **Стартовое событие** | Событие, стартующее сценарий; всегда определяет сущность (объект), которая попадает в начало цепочки маршрутов. Есть ограничение на кол-во раз исполнения |
| **Объект и контекст** | У каждого события есть **объект** (напр. Покупатель) и **контекст** (напр. «у покупателя изменился бонусный баланс», «покупатель осуществил покупку», «покупатель начал покупку») |
| **Фильтр (Условие)** | Элемент сценария, которому слева предшествует объект+контекст; условия фильтрации с результатом Да/Нет |
| **Действие** | Работает с объектом и его контекстом; действие порождает **контекст действия** |
| **Стартовый блок** | Состоит из событий и «расписаний» — оба чётко определяют объект, который ведётся по маршруту; действия/фильтры применимы только к совместимым (по типу объекта) элементам |

## Типы блоков схемы (сравнение с конкурентами)

Источник: `Блоки для сценариев лояльности.pdf`. Пять типов блоков; тип «Завершение» — на момент документа обсуждаем (`?`).

| Тип блока | Путь клиента (в последнем макете) | [[Mindbox]] | [[REES46]] |
|---|---|---|---|
| **Стартовое событие** | Флаг + функция-условие (`fx`) | «Событие» + иконка колокольчика, соединено с «Ожидание» | Зелёный блок «Событие» (пример: «Добавление в корзину») |
| **Условие** | (обсуждался вариант с ромбом — забракован директором как «не понятно») | «Условие» — воронка с да/нет-выходами (пример: «В сессии есть добавление в корзину») | Синий блок «Условие» (пример: «Подписан на канал») |
| **Действие** | Иконка + текст, напр. «Начислить 100Б, отправить Email» | «Группа шагов» (пример: «Отправить брошенную корзину») | Розовый блок «Сообщение» с CTR (пример: «Мобильные пуши», CTR 3.6%) |
| **Ожидание** | «10 дней» — пауза между шагами | «Ожидание 30 минут», окно выхода из блока 08:00–22:00 | Оранжевый блок «Пауза» (пример: «2 мин») |
| **Завершение** | Блок «Нет → Завершить» | Нет отдельного блока — заканчивается действием | Нет отдельного блока |

> [!note] Решение по «Условию»
> Вариант отображения условия ромбом был предложен, но отклонён директором («не понятно») — выбран текстовый/карточный формат вместо классической блок-схемной нотации.

## UI: реестр и карточка сценария («Концептуальное решение 3»)

**Новый пункт аккордеона** в разделе «Скидки и акции» → **«Сценарии»** (рядом со Скидками и акциями / Бонусами / Промокодами / Реферальной системой / Дисконтными картами).

### Реестр сценариев
- Слева — разделы сценариев (иерархия: «Давно не покупали», «Брошенная корзина», «День рождения», «Бонусы при регистрации» и т.д.)
- Справа — плоский список сценариев по разделу: раздел/название, кол-во покупателей за период, ответственный

### Карточка сценария — 5 вкладок

| Вкладка | Содержание |
|---|---|
| **Описание** | Название, `Запуск с даты` (начало действия маршрута), `Мин. интервал` (кол-во времени между повторными попаданиями клиента на маршрут), `Где используется` (обязательные условия-фильтры входа), блок **Цели** (связь цели с этапом-финишем + % достижения за период) |
| **Этапы** | Список этапов маршрута |
| **Схема** | Визуальная схема маршрута — правила перехода + действия между состояниями |
| **Проходы** | Запущенные/пройденные проходы клиентов по маршруту, карточка конкретного прохода |
| **Статистика** | Агрегированная статистика по сценарию |

> [!contradiction] Замечания к макету (не решены на момент документа)
> - **«Где используется»**: пример условия «в этой точке продаж пользователь долго не совершал покупку» признан неудачным — «он обязательно где-то совершает, а где-то нет… шляпа». Предложена альтернатива — пол/возраст покупателя. Открытый вопрос без решения на момент документа.
> - **Цели**: название «Промоакция сработала» заменено на «Вернули покупателя в магазин» — но концептуально поставлен вопрос, нужны ли обычным пользователям «цели» вообще, или достаточно понятия «конечный этап» (любой этап без исходящих переходов).

## Пример сценариев (из «Концептуальное решение»)

1. **Покупатель не активен (30 дней)** → начислить 100 бонусов → ожидание покупки 10 дней → ветвление: «Совершил покупку» (100) / «Не совершил покупку» (50) — числа на макете обозначают количество покупателей на этапе (`XXX`)
2. **Брошенная покупка** (не завершил покупку 2 дня) → напомнить рассылкой → ожидание завершения покупки 10 дней → аналогичное ветвление

## Открытый архитектурный вопрос

> [!contradiction] Не проработан вопрос масштаба
> Из «Концептуальное решение»: *«Самое главное — не проработан механизм поддержки проходов сотни тысяч покупателей по тысячам маршрутов в аккаунтах online!»* Также открыт вопрос, должен ли существующий механизм начисления бонусов за события в перспективе перейти на эту механику (маршруты) — на момент документа не решено.
