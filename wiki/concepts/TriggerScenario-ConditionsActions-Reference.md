# Список Условий/Действий — справочник событий/фильтров сценарного конструктора

> [!note] Общий справочник для всех сценарных документов проекта
> Этот документ — снятая с [[Mindbox]] полная таксономия событий-триггеров и фильтров-условий сценарного конструктора. Он используется как **словарь строительных блоков**, на который должны ссылаться остальные документы проекта [[CustomerJourney-Scenarios-Project]] (например, [[AbandonedCart-Loyalty-Scenario]] использует событие «Клиент покинул сайт или приложение» из категории «Действия клиентов» ниже).

> [!note] Заголовок обещает «Условия/Действия», содержимое — только «Условия»
> Несмотря на название документа, все 6 страниц источника документируют исключительно раздел **«Условия»** (Mindbox: события-триггеры + фильтры). Раздел «Действия» (Mindbox actions/шаги сценария — рассылки, SMS, push и т.п.) в этом PDF не раскрыт — либо ещё не задокументирован, либо перенесён в другой файл проекта (`Блоки для сценариев лояльности.pdf` или `События-действия для сценариев лояльности.sabydoc.pdf`, ещё не ингестированы).

## 1. Событийный каталог («Запуск по событию»)

Скриншот UI Mindbox (конструктор сценариев, узел «Событие», панель выбора события) показывает событие, сгруппированное по 8 категориям:

### Действия клиентов
- Выдано действие
- Выдано действие, связанное с продуктом
- **Оконченная сессия** (используется в [[AbandonedCart-Loyalty-Scenario]] как триггер)
- Список продуктов изменился
- **Брошенная корзина**
- Запрошен код авторизации

### Заказы
- Статус заказа изменён
- Заказ добавлен или изменён — ⚠️ подсказка UI: «Срабатывает при попадании заказа в БД и при любом изменении заказа. Для уведомлений об оформлении, доставке заказа и т.п. рекомендуется использовать событие изменения статуса заказа»
- Клиент приобрёл продукт (позиция доставлена)

### Сегментации
- Клиент попал в сегмент — ⚠️ подсказка UI: «Событие вызывается только для клиентов, которые попадают в сегмент **после запуска сценария**» (не для уже находящихся в сегменте на момент запуска)
- Клиент вышел из сегментации

### Изменения карточки клиента
- Изменился статус подписки
- Клиент попал в БД
- Изменилось значение дополнительного поля у клиента
- Обновление данных клиента
- Клиент зарегистрирован
- Первое подтверждение email
- Изменение email
- Email стал валидным
- Первое подтверждение мобильного телефона
- Изменение мобильного телефона
- Редактирование анкеты клиентом
- Клиент был сдедублицирован (deduplication)

### Изменения продуктов
- Предпочитаемый продукт изменился
- Продукт в списке продуктов изменился
- Просмотренный продукт изменился

### Лояльность
- Гашение промокода
- Изменения заданного баланса
- Бонусные баллы стали доступны (перешли из заблокированных)
- Выдан промокод
- Статус карты изменён
- Замена дисконтной карты
- Использован реферальный промокод клиента
- Баланс клиента стал отрицательным

> Пересекается с существующими подсистемами: [[Promocode-Subsystem-Overview]] (гашение/выдача промокода, реферальный промокод), [[Bonus-Programs-Architecture]] (заданный баланс, бонусные баллы, отрицательный баланс), [[DiscountCard-Subsystem-Overview]] (статус/замена карты).

### Рассылки
- Клиенту отправлена рассылка
- Клиент поучаствовал в рассылке

### Прочее
- Настало время Лучшего следующего предложения (Next Best Offer)

## 2. Расписание («Запускать каждый день»)

Альтернативный (не событийный) триггер запуска сценария:
- **Каждый день** — время + часовой пояс (пример: `14:00`, `UTC+03:00 Europe/Moscow`)
- По дням недели
- По дням месяца

Плюс блок **«Условия запуска»** (`+ Добавить условие`) — например условие «Клиенту» с под-опциями «Доступности промокода» / «Наличию продуктов в сегменте» (в источнике помечено «только одно» — взаимоисключающий выбор).

## 3. Условие (Condition) — построитель фильтров

Узел «Условие» проверяет выполнение фильтров **«по Клиенту»**, с логикой **«Все»/«Любое»** (кнопка «Еще ▾»), кнопками «Добавить фильтр» и «Добавить группу ИЛИ».

### Каталог полей-фильтров (панель выбора фильтра, срез 1)

- Email, Мобильный телефон, ID, Сегмент, Фамилия, Имя, Отчество, Пол
- **Дата рождения** — детализированный UI: режимы `заполнен и` / `заполнен и не` / `заполнен и любой` / `не заполнен`, диапазон дат с часовым поясом (`UTC+03:00`)
- Возраст, Зона, Подписка, Именины, Мобильное приложение, Устройство, AB-тест
- Задача импорта или редактирования
- **Заказы и списки продуктов** (группа) → Заказ, Позиции заказов (Покупки), Средний чек, Продукт в списке продуктов, Количество купленных продуктов
- **Программа лояльности** (группа) → Карта, Промокод, Текущий баланс, Сумма изменённого баланса
- **Рассылки** (группа) → Участие в рассылке, Рассылка отправлена, Рассылка не отправлена, Рассылка не доставлена, Открытие рассылки, Клик в рассылке, Запрос отписки

### Каталог полей-фильтров (панель выбора фильтра, срез 2 — расширенный)

- **Заказы и списки продуктов**: Заказ → Позиция заказа (Покупка) → Базовая стоимость, ID заказа, Из рассылки, Из механики, Оплата, Стоимость доставки, Стоимость заказа после скидок с учётом/без учёта [чего-то, обрезано в источнике]; Подробные данные → Канал последнего изменения, Точка контакта последнего изменения, Зона, Данные первого действия
- **Программа лояльности**: Применённые акции, Промокод, Выданный промокод, Промоакция; Карта, Текущий баланс, Сумма изменённого баланса
- **Другие действия**: Просмотры продуктов (фильтр вида «есть такие»), Просмотры категорий продуктов, Изменения списков продуктов, Действие клиента, Сессия, Количество дней с действием
