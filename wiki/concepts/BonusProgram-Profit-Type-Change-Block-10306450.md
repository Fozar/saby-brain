## Постановка и критерий

Первоначально под фичами lty_all_bp_balance/lty_all_bp_balance_d; по уточнению Козлобродова от 16.11 делать без фичи. Нужно запретить менять тип выгоды бонусной программы, если по ней уже были бонусные операции. Сейчас предупреждение позволяет подтвердить и продолжить; нужно предупреждение без возможности сохранить изменение.

## Что выяснено по коду

Проверка check_bonus_type_change_rule находится в promotion/helpers/validation_rules.py Online-модуля и вызывается из Promotion._check_promotion_type_rules до сохранения. Условие: прежний тип BONUS, новый не BONUS, существует запись в ВидЦеныДокумент по акции. SQL не меняли. ConfirmWarningContext перехватывает только ConfirmWarning; обычный sbis.Warning не подавляется через Force. Тесты в tests/tests_priceformationonline/loyaltyprograms/promotion/validation_rules.py проверяют отказ с Force и без него, разрешение без операций и без смены бонусного типа. Это пока непрогнанные тесты, не доказательство исправления.

## Решения и почему

Менять реакцию существующей проверки, не придумывать новую систему проверки. Слово «ошибка» в разговоре означает запрет продолжения; карточка требует варнинг без подтверждения.
