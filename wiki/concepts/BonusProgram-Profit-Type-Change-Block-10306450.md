# Запрет смены типа выгоды после бонусных операций

## Задача

№10306450: https://online.sbis.ru/opendoc.html?guid=01a18c33-04f8-7b62-8b85-137eda712c62&client=3

Ноябрьский план №606980697, пункт `634582942`. Срок пункта: **2026-11-30**; срок карточки: **2027-04-28**. Плановая оценка: 0.5 ч (как возвращено СБИС, не переоценивалась).

**Сроки расходятся:** сохраняем оба; перенос срока плана из более поздней даты карточки не следует.

Веха: не проверена; дата плана не заменяет веху.

## Где остановились

09.11.2026: заведена страница по ноябрьскому плану и встрече с Матюшевым. Это фиксация контекста, не отчёт о выполненной разработке.

08:21–08:23: точка проверки уже есть; нужно заменить подтверждаемое предупреждение на безусловный отказ. Матюшев предупредил о контекстном механизме накопления предупреждений; детали разберём при выполнении, если возникнут вопросы.

## Постановка и критерий

Под фичами lty_all_bp_balance/lty_all_bp_balance_d запретить менять тип выгоды бонусной программы, если по ней уже были бонусные операции. Сейчас предупреждение позволяет подтвердить и продолжить; нужно предупреждение без возможности сохранить изменение.

## Что выяснено по коду

Код при ingest не разбирался. Имена методов и описание текущего поведения выше взяты из карточки задачи и разговора; они не подтверждают состояние текущей ветки.

## Решения и почему

Менять реакцию существующей проверки, не придумывать новую систему проверки. Слово «ошибка» в разговоре означает запрет продолжения; карточка требует варнинг без подтверждения.

## Открытые вопросы

Найти нужный тип исключения в действующем механизме предупреждений. Разница сроков плана и карточки не объяснена.
