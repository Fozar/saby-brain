# SabyGet: превью ДК на странице заведения в новом дизайне

Задача в разработку №09234904 ([ссылка](https://online.sbis.ru/opendoc.html?guid=01a0cd72-fa62-7a81-8ecf-3574e33cb31e&client=3)), автор и ответственный Михель В.М., веха 26.6100, срок 28.11.2026. Этап «11 Карты в сабигет» проекта [[DiscountCard-Design-Constructor-Project]]. UI (компонент отображения ДК и хелпер предзагрузки `getDesignViewData(siteId, cardId, templateId)`) делает Лебедева Н. Парная задача про выданную карту: [[SabyGet-Issued-Card-Design-Constructor]] (№09234998).

## Что просила постановка

БЛ: добавить `SiteID` в `Card.GetListV2` из `CardTemplate.SiteId`; SabyGet протягивает его в `Establishment.BonusDetails`. Для хелпера ТЗ предлагает `siteId = BonusDetails.SiteID`, `cardId = CardPreview.ID`, `templateId = Card.Template.ID`. В заметках: новый дизайн показывать, если у владельца дизайна включена фича `dc_design_new` и есть `SiteId`, иначе старая логика.

## Что выяснено по коду

- **Превью не выданной карты идёт не из `Card.GetListV2`.** SabyGet берёт `CardPreview` из online `LoyaltyProgram.GetDescriptionBySalePointV2`, поле `Template` (`sgr_establishments.py:51`, `referral/bonus_system/base.py:138,200`). Его собирает price-formation `discountcard/discountcardtype/get_template.py`. `Card.GetListV2` попадает в `BonusDetails` только для выданной карты, тогда `CardPreview` перезаписывается шаблоном карты (`bonus_info.py:150`).
- **`Template.ID` превью — это ID типа карты онлайна, а не дизайна.** ID дизайна (ПО ДизайнКарты) — `@Template` из `DiscountCardTemplate.Read`. Карты на этапе превью нет, `cardId` передавать нечего. ТЗ в этой части неточно; по решению Тимошенко постановщику об этом не сообщали.
- `DiscountCardTemplate.Read(card_type_id)` уже отдаёт и `@Template`, и `SiteId`, поэтому новые поля не требуют лишних запросов.

## Решение (согласовано 12.10, поправлено по ревью)

- **СДК (discount-cards):** `Card.GetListV2` / `Card.ReadV2` отдают `SiteId` внутри `Template` (поле формата `TEMPLATE_FORMAT`, UUID, в `.orx` после `ShowDescription`) из активного дизайна типа карты, без проверки фичи (список карт из разных аккаунтов, фичу владельца дёшево не проверить). Для брендбука, хранимой карты и карты без дизайна онлайна `None`. Коммит перенесён из №09234998 в эту задачу.
- **Online (price-formation):** `get_template` отдаёт в `Template` поля `DesignID` (`@Template`, int) и `SiteId` (uuid, только при включённой `dc_design_new`, иначе `None`). Поля объявлены в обеих версиях `GetDescriptionBySalePointV2` в `LoyaltyPrograms.orx`. Фронту хватает одного условия «`SiteId` заполнен».
- Имя поля `SiteId`, как у колонки `CardTemplate.SiteId`. Сначала было `SiteID` (по постановке и по соседним `LogoID`, `StripID`), переименовано по замечанию ревьюбота в MR !28051.
- Участник франшизы: шаблон читается у владельца, фича проверяется у участника. На практике не влияет: сетевые карты на конструктор не переводят.

## Звонок с Лебедевой 21.10: дорабатываем Card.GetListV2

Подробности: [[zvonok-lebedeva-timoshenko-2026-10-21]]. Отдельный метод отклонён.

- Отдельный метод не делаем. Дорабатываем `Card.GetListV2` (через него же `Card.ReadV2`), он общий для всех экранов SabyGet.
- **Условие нового дизайна: есть `SiteId` и у владельца дизайна включена `dc_design_new`.** Только `SiteId` мало: после конвертации карт фичу могут аварийно выключить, и тогда должны вернуться старые данные. - Под условием в `Template` отдаём цвет фона и картинку баннера (их берёт реестр «Карты») и дополнительно `SiteId`, `LoyaltyCardDesignId` и идентификатор карты (если запрошена конкретная карта). В документе Лебедевой: «в поле Template возвращаем только баннер и фон», в звонке перечислены все пять полей.
- Если получать фон и баннер для конструктора дорого, вынести их в доп. поля, чтобы не нагружать вызов в реестре. Лебедева считает, что все данные лежат в discount-cards и сторонних сервисов не нужно; Тимошенко в звонке подтвердил «вроде бы да».

## Разбор кода SabyGet 21.10 (после звонка)

Код `sabyget/core` и `sabyget/referral` ветки `rc-26.6100` (поверхностный клон) и discount-cards `rc-26.6100`.

- **Превью невыданной карты идёт из online, документ Лебедевой неточен.** `CardInfoByEstParams` кладёт в `CardPreview` поле `Template` из `GetDescriptionBySalePointV2` (`referral/bonus_system/base.py:200`). `FullCardList` -> `Card.GetListV2` отдаёт только выданные карты. В `get_bonus_details` (`sabyget_service/discount_cards/bonus_info.py:178-184`): нет карты, есть превью, тогда `Card = {Template: CardPreview, EmissionBarCode: CardPreview.TypeBarCode}`; есть карта, тогда `CardPreview = Card.Template`. Фронт всегда читает `Card.Template`, отсюда впечатление, что `CardPreview` не используется. Online-часть (!152256) нужна; имена новых полей в обоих источниках должны совпадать (сейчас в online `DesignID`).
- **Фильтры `Card.GetListV2`:** страница заведения `ClientID` + `SalePoint` (или `ShopID`); реестр «Карты» `Keys`, `ForSiteList` (`GetCardListShortFrm` -> `CardList` -> `FullCardList`); диалог выданной карты `Card.ReadV2(card_id)`, внутри СДК `Keys` + `WithStampsOnBanner=True`; `referral/operations/base.py:477` `ClientID` + `SearchString`, читает только `SalePointList`. Признака «нужен плеер» SabyGet не передаёт.
- **`WithStampsOnBanner`** SabyGet не передаёт, выставляет только `Card.ReadV2`. В `GetListV2` работает только в ветке брендбука (`_get_template_from_brand_book`, кеш `CardType.Info.StampsBannerImage`); для дизайна на конструкторе ветки нет, хотя кеш картинок для конструктора уже генерируется (№09236765).
- **Баннер дизайна на конструкторе теряется.** В `ViewDetails` конструктора ключи `Logo`, `Banner` (URL строкой), `BackgroundColor` (`appobjectimpl/loyaltycarddesign/write.py:_set_images`). У такого дизайна нет `ApplicationKey`, `GetListV2` идёт в общую ветку: `BackgroundColor` и `Logo` читаются (ключи совпадают), баннер нет: SQL берёт `Strip`/`StripID`. На Inside `get_admin_list` уже читает `ViewDetails->>'Banner'`.
- **Реестр «Карты» SabyGet:** картинка `FrontImg`, затем `TmplFrontImg` (= `OrgLogo`); `Template.StripImageUrl` приоритетен в `common.py:59`; фон `Template.BackgroundColor`.
- **Бэк SabyGet отбросит новые поля:** `BonusCard.Read` описывает формат `Template` списком полей, `read_card` (`user_cards.py`) приводит запись через `MergeRecords` к `BonusCard.Read/2`. Новые поля надо добавить в их форматы (`BonusCard.Read`, `Card` в `Establishment.BonusDetails`). Не проверено на стенде.

**Что отсюда для ТР `GetListV2`:** баннер конструктора (`ViewDetails->>'Banner'`) и баннер со штампиками при `WithStampsOnBanner`; новые поля `SiteId`, `LoyaltyCardDesignId` (= `Template.ID`), `CardUUID` под условием; в online переименовать `DesignID`.

**Документ для SabyGet:** черновик `docs/sabyget-new-design-dc.md` в price-formation (не в git), 21.10.
