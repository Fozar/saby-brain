# Путь клиента — Сервис Маршрутов (backend API)

Navigation: [[CustomerJourney-Scenarios-Project]] | [[CustomerJourney-WorkPlan]]

Проектируемая backend-архитектура платформы маршрутов для сценариев лояльности, извлечена из «План работ по проекту.pdf» (этапы 1.2, 2.1, 2.2). Реализуется существующим на платформе **Сервисом Маршрутов** (используется другими прикладными конструкторами, см. [[Saby-Scheme-Constructors]]) совместно с новыми **Сервисом Выборок** и **Сервисом Триггеров**.

> [!note] Статус
> Планируемые методы, ещё не реализованы на момент документа (план работ, срок проекта — 27.03.2027). Соответствует ранней стадии проекта, см. [[CustomerJourney-Scenarios-Project]].

> [!contradiction] Расхождение имён методов с финальным ТЗ
> [[Route-Platform-Architecture]] (построена на **согласованном** `Техническое задание.pdf` — более позднем документе того же проекта) фиксирует другие имена методов авто-проходчика: `RouteService.StartTrace`, `RouteService.StartClientRoute`, `RouteService.OnEvent` — вместо `AutoTrace.Start/Run/OnEvent` этой страницы. Похоже на переименование между стадией планирования и финальным ТЗ, не подтверждено текстом источников напрямую.

## Компоненты

### Сервис Маршрутов
Хранит схемы маршрутов и статистику проходов (переход от узла к узлу по определённому ребру — «Концептуальное решение»). Проход выполняется прикладниками (командой Системы лояльности) поверх платформенных средств и наработок команды Скриптов.

**Методы карточки сценария (CRUD):**
- `Create/3` — создание карточки маршрута
- `Read/3` — чтение карточки сценария
- `Update` — фиксация изменений в маршруте

**Методы запуска/управления:**
- `Route.StartTrace/2` — постановка маршрута на прохождение (для сценариев: разовый / по событию / по таймеру); включает валидацию входных параметров, запуск сбора выборки, фиксацию в статистику
- `Route.Start/1` — запуск сценария
- `Route.Stop/1` — остановка сценария
- `Route.Status/1` — статус сценария

**Авто-проходчик маршрутов** (крупнейший тех. этап проекта, 59 дней):
- `AutoTrace.Start/3` — запуск авто-проходчика: на вход маршрут, набор клиентов, параметры запуска; для каждого клиента вызывает `AutoTrace.Run/3` (создаёт новый проход)
- `AutoTrace.Run/3` — создание нового прохода по маршруту для клиента
- `AutoTrace.OnEvent/3` — продолжение прохода по событию/таймеру/действию

Модуль исполнения этапа в зависимости от типа (реализация — крупнейший блок работ, ~30 чд): этап действие, этап условие, этап ожидание (включая скрытые/не запущенные триггеры, которые запускаются и останавливаются самим маршрутом), этап завершение, этап логический блок, переход между этапами, фиксация в статистике.

### Сервис Выборок
Отвечает за выборки клиентов (сегменты), которыми маршрут комплектуется при разовом/периодическом запуске.

- Новые параметры `SaveSelection`: отложенный запуск, одноразовая выборка, callback для ошибок
- `StartSelection` — запуск сбора отложенных выборок
- Новый метод проверки вхождения вектора сущностей в выборку

### Сервис Триггеров
Доработка механизма создания/запуска/удаления триггеров с бизнес-логики. Отвечает за callback получения информации о завершении этапа «Действие» (положительное/отрицательное).

## Событийный слой (Этап 1.1 «Триггерные события»)

Отдельный крупный технический этап (93 дня) — источник событий/целей для маршрутов, детали событий/действий см. [[CustomerJourney-Events-Actions-Catalog]]:
- js-api метод скрипта трекинга для добавления цели в пакет отправки данных трекинга
- API-метод оркестратора прикладных обработчиков достигнутых целей за период
- Обработчики оркестратора для «поднятия» триггерных событий
- Метод чтения списка последних событий по визитам в разрезе времени
- Указание в атрибутах визита факта достижения пользовательских целей
- Расширение списка обрабатываемых целей при отправке данных из БМП (боевой мониторинг производительности / брокер?)

## Глобальная пред-фильтрация (Этап 2.5)

Платформенная поддержка глобальных ограничений на попадание клиента на маршрут: «режим тишины», «ограничить срабатывания», «не чаще» — настраивается через «шестерёнку» на странице сценариев лояльности, применяется ко всем сценариям сразу.
