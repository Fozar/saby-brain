# Статус корешка не обновляется в реестре при фильтре по статусу

## Задача

Ошибка на стенде №102210097, автор Земцова А.В. Ссылка: https://online.sbis.ru/opendoc.html?guid=01a163ad-1046-7ba5-9942-e66b2bd07ef4&client=3
Веха 26.5118 online/inside, срок 27.10.2026. Стенд fix, портал «Банковская РС», офферы, страница owner-deals.

## Где остановились
Свешников (23.10 08:58) выбрал вариант 2: строка остаётся в списке с новым статусом, пока фильтр не перестроят. Тимошенко 23.10: правка всё же на бэке. Сделано 23.10 на бэке: в `GetStubList` при заданном `StubId` не применяются `Status` и период по дате статуса (период по дате создания не меняется, его оставили); `ProgramId` и `PartnerId` остаются (доступ партнёра). `Search` не трогаем: имя клиента сменить нельзя (Тимошенко). Ветка `26.5118/bugfix/aatimoshenko/102210097` от `rc-26.5118`, закоммичено `da59447216`, запушено, MR создан 23.10. Замечание бота (Low): описания `StubId` и `Date` в `ReferralProgram.orx` и docstring `Date` не говорили, что при `StubId` статусные отборы не применяются; поправлено 23.10 через amend, коммит `9edeebfb06`. Затем 23.10 добавлен комментарий в код с причиной (реестр перечитывает строку с теми же фильтрами, со старым статусом или датой статуса корешок не находится), тоже amend, коммит теперь `61d7974e91`, force-with-lease; worktree `D:/dev/wt102210097`. MR создан 23.10 (документ 632362169, приложение online, GitLab !152847-!152855 по веткам вехи), ждёт ревью. 3 новых теста, 27 тестов класса OK, до фикса два красных. Не проверено: режим без `ref_deals_convert` (`GetLeadList`, фильтры `Result`, `Deleted`) - вероятно та же картина, вне задачи. Видео к задаче не приложено (Тимошенко написал Земцовой 23.10 06:38), есть скриншот и .sbislogz.

## Что выяснено по коду
- По логу: при фильтре «В работе» (`Status: 10`) после `ReferralProgram.UpdateStub` (статус 20) фронт точечно перечитывает строку через `GetStubList` с `StubId` и теми же фильтрами. Корешок уже не в статусе 10, ответ пустой, строка остаётся как была.
- В `get_stub_list.py` `StubId` и `Status` складываются через AND. Docstring называет `StubId` «для точечного обновления».
- В том же логе ошибка фронта `Controls/filterPanelEditors:Dropdown: resetValue ... multiSelect` — к задаче не относится, можно упомянуть отдельно.

## Решения и почему
Первое предложение (при `StubId` не применять `Status`) снято по замечанию Тимошенко 23.10: если корешок не проходит под фильтр, из реестра он и должен пропасть. Бэк отвечает правильно (пустой список). Строку убирает фронт: `client/LoyaltyOnline/ReferralLeadNew/Owner/_deals/View.tsx` после сохранения вызывает `dealsSlice.reloadItem(key, { method: 'query', replace: true })` и на пустой ответ ничего не делает. Какое поведение у `reloadItem` на пустом ответе (платформа) или нужна правка View.tsx, не проверено. Фронт не наш, правка только по явной просьбе.
