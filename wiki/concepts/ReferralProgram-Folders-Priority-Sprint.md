# Папки, приоритеты и плиточный реестр программ (спринт №2)

Navigation: [[ReferralProgram-Part2-Project]] | [[ReferralProgram-Data-Model]] | [[ReferralStub-LeadSum-Implementation]]

Спринт **«Добавление папок и приоритетов реф. программ + изменения согласно макетам»**, концепт от 11.12.2025 ([[Самарина-Ирина|Самарина И.]]), плановая смета от 10.12.2025 (Точилова Д.). Срок — 26.2100 / 30.04.26. Объём — **78 дней** (55 работ + 23 технологических).

Раздел «Офферы» переименовывается в **«Программы»**.

---

## Задачи

1. Владелец создаёт **папки** (стандартный механизм Saby) и группирует программы; Партнёр видит настроенные Владельцем папки с доступными ему программами.
2. **Плиточное и списочное** представление раздела.
3. Инструмент **пользовательской сортировки** (приоритет отображения плиток) в корне и внутри папки.
4. Вкладка **«Описание»** в карточке программы у Партнёра.

## Техническая реализация — БЛ

> [!key-insight] Схема БД не меняется — иерархия уже есть в `ВидЦены`
> Офферы хранятся в `ВидЦены`, где иерархия уже поддержана платформой, поэтому папки реализуются стандартным механизмом: папка = запись `ВидЦены`-раздел, принадлежность оффера — `ВидЦены.Раздел`.

**Доработки существующих методов:**

| Метод | Что добавляется |
|-------|-----------------|
| `ReferralProgram.Create` | возможность создать папку |
| `ReferralProgram.Read` | `Folder: number` (ид. папки = `ВидЦены.Раздел`), `FolderName: string` (для предзагрузки названия) |
| `ReferralProgram.Update` | обработка `Folder` — добавление оффера в папку |
| `ReferralProgram.GetList` | фильтры «только папки / только листья», «записи конкретной папки», возврат полей иерархии и пункта «Все» (корень); рекордсет вложенных офферов в записи папки (только непосредственные дети, без вложенных папок); поля статистики; фильтр `IsJoined` |
| `ReferralProgram.GetLeadPeriodList` | `LeadCount: number` — количество заявок за период (по аналогии с `GetPartnerList`) |

**Новый метод** `ReferralProgram.Move` — по сигнатуре платформенного `IndexNumber.Move`:
- `ObjectId: number` — перемещаемый оффер
- `DestinationId: number` — оффер, относительно которого перемещаем
- `Order: 'after' | 'before'`

Один и тот же `Move` используется и для перемещения между папками, и для ручного изменения порядка.

### Поля статистики в `GetList`

- `CustomerCount` — количество посетителей
- `LeadCount` / `PositiveLeadCount` — количество сделок / завершённых положительно
- `LeadSum` / `PositiveLeadSum` — сумма по сделкам / по завершённым положительно
- (сумма вознаграждения)

> [!key-insight] `LeadSum` заказан не только для `GetPartnerList`
> Задача №08052776 ([[ReferralStub-LeadSum-Implementation]], 2026-08-06) наполнила колонку `Сумма` `ВидЦеныДокумент` и отдала `LeadSum` в `GetPartnerList`/`ReadStub`/`GetStubList`. Этот спринт (декабрь 2025) требует те же `LeadSum`/`PositiveLeadSum` ещё и в **`ReferralProgram.GetList`**, а спринт №3 — в **`GetListByContractor`** ([[ReferralProgram-ContractorCard-Programs-Tab]]). То есть после наполнения колонки работа по выдаче суммы наружу закрыта не полностью.

### Отказ от сервиса Маркетинга

> [!key-insight] Корешки как источник статистики зафиксированы здесь, в декабре 2025
> Дословно из тех. реализации спринта: *«По факту создания Сделки\Заявки по реф. программе будет всегда создаваться `ВидЦеныДокумент` с мета-информацией о сделке\заявке (с последующей установкой суммы вознаграждения — если вознаграждение положено). И уже на основе этих данных будет строиться статистика. По факту смены фазы сделки\заявки мета-информация в `ВидЦеныДокумент` будет обновлена событием.»*
> Оценка — **«Хранение статистики на основе ВидЦеныДокумент + конвертация текущих боевых данных + отказ от получения статистики через сервис Маркетинга — Тимошенко А. 7д»**. Это первоисточник линии работ [[ReferralProgram-Stub-Implementation]] → [[ReferralStub-Backfill-Service-Method]] → [[ReferralProgram-RefDealsConvert-Feature]], растянувшейся далеко за 7 дней.

### Курсорная навигация заявок

Вкладка «Заявки» в детализации: месяц в master — не фильтр, а **позиционирование**; в detail всегда весь список с самой ранней заявки.

БЛ (по образцу реестра «Бонусы / Покупки», `Bonus.GetSaleList`):
- двухсторонняя курсорная навигация по дате, курсор принимает **любую** дату;
- возвращать ровно запрошенное количество записей (не хватает — добираем более ранними).

Оценка: **Тимошенко А. 6д** — «по опыту страницы Бонусы/Покупки, функционал сложный, лучше заложить ×2 времени на ошибки». UI — [[Ютман-Элина|Ютман Э.]]. См. [[CursorNavigation-Mechanism]], [[LoyaltyPrograms-IterativeListLoading]].

### Индикатор и фильтр участия

`ReferralProgram.GetList` + фильтр `IsJoined: boolean` — проверка участия **по наличию `AdObject`**:
- `true` — только офферы, где партнёр участвует;
- `false` — только те, где не участвует;
- не передан / `null` — все.

UI: фильтр «Все программы / Участвую / Не участвую», плашка «Участвую» по наличию `AdObject` в ответе. Явное указание в концепте: *«в макете не стандартный фильтр, делаем стандартный»*.

## Техническая реализация — UI

- Новая разводящая «Офферы» на стандартном **MasterDetail**: в мастере — список папок, в дитейле — офферы выбранной папки (по умолчанию все). Платформенный проводник с кастомными элементами: плитка папки (со списком офферов внутри) и плитка оффера со статистикой.
- Переключение представлений — платформенное действие `Controls/actions:ViewMode`, для таблицы отдельный шаблон элемента; **доработок БЛ не требует**.
- Выбор папки в шапке карточки оффера — стандартный `Controls/listCommands:MoveWithDialog`; если папка не выбрана, пишем «в корне».
- Перемещение записей — [стандартный механизм](https://wi.sbis.ru/doc/platform/developmentapl/interface-development/controls/list/actions/operations/commands/move/) + drag-n-drop.
- Страница **«Объявления» удаляется**, компонент маркетинга переносится на новую страницу **«Описание»**; копирование реф. ссылки переводится на платформенное действие «Поделиться ссылкой».
- Партнёр папки **не создаёт и не редактирует**; папка без доступных партнёру программ **не отображается**.
