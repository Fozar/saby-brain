# Antigravity Auto-Approve Hub — Архитектура, 4 уровня и AI-супервизор

Локальный сервис (`http://127.0.0.1:8125`) предварительной фильтрации действий для `agy` (Antigravity CLI) через pre-tool hook. Реализует оптимистичную модель безопасности разработки: рутинные безопасные команды и правки файлов выполняются мгновенно без подтверждения в терминале, а редкие деструктивные операции блокируются или вызывают принудительный запрос подтверждения.

## 4-уровневая модель безопасности

1. **`allow`** — детерминированный fast-path (<1 мс, 0% CPU):
   - Белый список dev-утилит: `git` (штатные команды), `python`, `pip`, `uv`, `npm`, `cargo`, `docker`, `pytest`, системные утилиты просмотра (`ls`, `grep`, `curl` и др.).
   - PowerShell-командлеты инспекции: `Get-*`, `Select-*`, `Test-*`, `Invoke-RestMethod`, переменные `$var = ...`.
   - Workspace Trust: автоматическое одобрение записи/редактирования файлов внутри каталогов проектов (`PycharmProjects`, `agy-auto-approve`) и `scratch`-папок диалогов.
   - Чтение файлов и read-only методы MCP-инструментов.
2. **`deny`** — катастрофические действия, блокируются мгновенно:
   - Массовое удаление корня/дисков (`rm -rf /`, `del C:\*`).
   - Форматирование разделов (`Format-Volume`, `mkfs`, `dd if=`).
   - Удалённое выполнение непроверенных скриптов вслепую (`curl url | bash`), fork-бомбы, reverse shell.
3. **`force_ask`** — действия с высоким риском потери данных (игнорируют "Always allow" CLI и требуют подтверждения):
   - Разрушительные git-операции: `git push --force` (`-f`), `git reset --hard`, `git clean -fdx`, `git branch -D`.
   - Удаление БД (`drop database`, `drop table`, `truncate table`).
   - Модификация системных файлов (`C:\Windows`, `hosts`, `/etc/`).
4. **`ask`** — сомнительные или нестандартные действия:
   - Передаются на стандартную проверку прав Antigravity CLI (где учитывается кэш "Always allow").

## Режимы работы

| Режим | Описание | Задержка |
|---|---|---|
| **`rules`** | Только regex-правила и списки. Сомнительные команды требуют подтверждения в CLI. | <1 мс |
| **`yolo`** | Максимальный автоаппрув без остановок. Блокирует только `deny`-паттерны. | <1 мс |
| **`smart`** | Не прошедшие fast-path команды отправляются в локальную Ollama (на домашнем сервере/ноутбуке через SSH-туннель `11434`). | ~1.5–6 сек |
| **`gemini`** | Не прошедшие fast-path команды отправляются в облачную Gemini Flash Lite через корпоративный прокси `193.39.208.98:3128`. | ~1.1 сек |
| **`manual`** | Автоаппрув отключен, все действия запрашивают подтверждение в терминале. | — |

## Сравнение моделей супервизора

В тестах на 12 типовых сценариях разработчика:
- **`qwen2.5-coder:1.5b`**: чрезмерная паранойя, падает в `ask` на штатных командах разработки (`docker build`, `pip install`, правка файлов проекта).
- **`qwen2.5:3b`**: адекватная оценка большинства команд (~1.5 сек), но ошибочно считает изменение проектных файлов с пометкой `external` поводом для отказа `deny`.
- **`gemini-flash-lite-latest` (3.5)**: наивысшая точность (~1.1 сек). Корректно понимает структуру путей, не путает проекты с системными каталогами, строго следует ТЗ по разделению `force_ask` и `deny`.

## Инфраструктура запуска

- **Автозапуск Windows**: `startup_hidden.vbs` при входе пользователя скрытно поднимает SSH-туннель к `Host cachegrid` (`LocalForward 11434 192.168.0.94:11434`) и запускает hub (`uvicorn src.server:app --port 8125`).
- **Веб-дашборд**: `http://127.0.0.1:8125` со статистикой, переключением режимов и живым логом WebSocket.
