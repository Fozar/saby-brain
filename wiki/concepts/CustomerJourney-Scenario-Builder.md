# CustomerJourney Scenario Builder

Механика визуального конструктора сценариев («Путь клиента» — [[CustomerJourney-Scenarios-Project]]). Источник: `Примеры различных сценариев со схемами.pdf`, раздел «Отбор клиентов / Действия / События / Условия на схеме» (стр. 10–14).

## Строительные блоки схемы (по диаграммам)

Каждая схема — блок-схема в духе BPMN, наблюдаемые типы узлов:

| Узел | Форма/цвет | Назначение |
|---|---|---|
| **Старт** | синий скруглённый прямоугольник (флажок) | Событие в реальном времени ИЛИ регулярная/разовая выборка сегмента |
| **Условие** | голубой ромб | Ветвление Да/Нет по доп. условию |
| **Действие** | зелёный прямоугольник | Отправить email/SMS/push, начислить бонусы, выдать промокод и т.д. |
| **Ожидание (race)** | жёлтый шестиугольник с иконкой часов | «Ждём N дней ИЛИ наступление события X» — гонка между таймером и целевым событием |
| **Цель достигнута** | зелёный круг | Терминальное состояние успеха |
| **Цель не достигнута** | красный круг | Терминальное состояние неуспеха (таймаут) |

## Два типа старта

1. **Событийный (real-time)** — сценарий реагирует на конкретное бизнес-событие Saby в момент его наступления (например, «Совершена покупка», «Создание нового клиента», «Получено сообщение в чате»). Событие + доп. условия фильтруют, кому запускать сценарий.
2. **Выборка/расписание (batch)** — сценарий периодически (ежедневно/еженедельно/ежемесячно) или разово опрашивает базу клиентов по сегментному фильтру («Выборке») и запускает цепочку для всех подходящих. Используется для профилактических/проактивных сценариев (сгорание бонусов, дни рождения, реактивация).

## Декларативная структура сценария

Каждый пример в каталоге описан единообразно:
- **Описание** — свободный текст логики
- **Цель** — целевое событие/состояние, определяющее успех
- **Стартовый блок** — Событие ИЛИ Выборка + Доп. условия (+ Расписание для batch-сценариев)

## Race-паттерн ожидания

Доминирующий паттерн во всех схемах: после первого действия сценарий уходит в узел ожидания вида **«Ждём N дней ИЛИ событие X»**. Если событие X наступает раньше таймера — ветка «Да» → Цель достигнута. Если истекает таймер — ветка «Нет» → Цель не достигнута (иногда — доп. финальное действие типа «Отправить напоминание» перед закрытием).

Исключение — «Награда за частые покупки»: там после ожидания повторно **проверяется то же самое условие** («Покупок > 5?») вместо гонки с новым событием — паттерн переоценки метрики, а не ожидания реакции.

## Каскадные (multi-touch) сценарии

Пример «Сезонное предложение для покупателей сезонных товаров» показан в двух вариантах:
- **Простое** — один email + один race-узел (single-touch)
- **Каскад** — 3 последовательных email'а («Ранний доступ», «Сезон открыт», VIP-напоминание «Товары заканчиваются») с race-узлом ожидания между каждым; покупка на любом шаге ведёт в общую «Цель достигнута», истечение всех таймеров — в «Цель не достигнута». Это drip-campaign паттерн поверх той же примитивной схемы блоков.

## Унификация условий: Выборка = внутрисценарные условия

Явный принцип проектирования (стр. 10): *«Набор этих условий должен пересекаться (быть унифицирован) с общими условиями для выборок. В данном случае мы используем те же самые параметры фильтрации, но применяем их для проверки конкретного пользователя уже в процессе прохождения запущенной цепочки»* — то есть один и тот же набор фильтров/параметров используется и для формирования стартового сегмента, и для условных проверок внутри уже запущенного экземпляра сценария.

## Каталог фильтров/условий (панель «Отбор клиентов»)

Источник фильтров — существующая панель «Триггеры» Saby CRM (`saby` приложение, раздел «Маркетинг»). Красным в макете выделены параметры/условия, нужные для MVP; часть требует доработки (правая колонка):

| Категория | Параметры |
|---|---|
| Профиль клиента | Дата регистрации; Не участвует в сценариях (нужно доработать); Кол-во отправленных email за 24ч (нужно доработать) |
| Лояльность и Бонусы | Сгорание бонусов (через N дней); Участие в реф. программе (Привёл > N друзей, Статус = Реферал); Промокоды (Есть активный / Применял ранее) |
| Корзина | Товары в корзине (Есть/Пусто/Сумма > 1000₽); Товары в избранном (> N дней) |
| Физлица/Регион | Пол, Возраст, День рождения, Владельцы карт, Кол-во бонусов, Есть телефон/Email |
| Покупали | Что/Где/Когда, День недели/Во сколько, Количество, Сумма/Средний чек, В розницу/По счету, Источник заказа, С доставкой |
| Контакты | Тема/Вид/Итог, Ответственный, Просроченные, С отзывами, Подключались к Wi-Fi |
| Регион | Кроме, По спискам клиентов, Доп. поля, Подписчик Saby Get |
| Компании | Кроме избранных, Дата регистрации |

Полная справочная таблица условий (стр. 13–14):

| Категория (Интерфейс) | Параметр / Условие |
|---|---|
| Физлица / Регион | Пол, Возраст |
| География | =/≠/содержит (город, регион, список) |
| Дата рождения | Сегодня, Завтра, В этом месяце, Через N дней |
| Дата регистрации | =/>/< дата |
| Теги / Кастомные поля | Содержит тег; Поле = значение |
| Покупали (Активность) | LTV (сумма всех покупок) |
| Количество покупок | >/</= число (за всё время / за период) |
| Средний чек | >/</= сумма |
| Дата последней покупки | >/< N дней назад |
| Состав покупки | Содержит/Не содержит товар или категорию |
| Способ оплаты/Доставка | = Карта/Бонусы/Наличные, = Курьер/Самовывоз |
| Корзина и Избранное | Сумма корзины >/</= сумма; Товары в избранном (Есть/Нет, > N дней) |
| Лояльность и Бонусы | Баланс бонусов; Сгорание < N дней; Дисконтная карта Есть/Нет |
| Реф. программа | Привёл > N друзей; Статус = Реферал |
| Промокоды | Есть активный / Применял ранее (Код = "XXX") |
| Контакты и Отзывы | Email/Телефон; Реакция на рассылки Открыл/Кликнул (нужно доработать); Оставил отзыв (Да/Нет), Оценка >/< балла |

## Каталог действий

| Действие | Описание | Параметры настройки |
|---|---|---|
| Отправить Email/SMS/Push | Персонализированное сообщение | Шаблон, динамические поля ({Имя}, {Товары из корзины}, {Скидка}) |
| Начислить бонусы | Добавить баллы на карту лояльности | Сумма, срок действия, причина |
| Выдать промокод | Персональный промокод | %/сумма, товары, срок действия |
| Добавить/удалить пометку | Тег клиента | Например "VIP", "Риск оттока" |
| Добавить/убрать из папки клиентов | Переместить клиента в папку | — |
| Назначить скидку | Персональная скидка (для клиента/списка клиентов) | — |
| Выполнить код | Произвольный кастомный обработчик | — |
| ~~Отредактировать клиента~~ | ФИО/телефон/email/дата рождения/адрес/доп. поля/комментарии | **Вычеркнуто в макете** — вне MVP-скоупа |
| ~~Выдать дисконтную карту~~ | Создание эл./пластиковой карты, привязка к клиенту | **Вычеркнуто в макете** — вне MVP-скоупа |

> [!key-insight] MVP-скоуп сужен
> В макете два действия — «Отредактировать клиента» и «Выдать дисконтную карту» — явно вычеркнуты (strikethrough), то есть исключены из первой итерации конструктора, хотя описаны как потенциально полезные.
