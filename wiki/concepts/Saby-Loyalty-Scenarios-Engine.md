# Saby Loyalty Scenarios Engine («Сценарии лояльности»)

Визуальный конструктор маркетинговых сценариев (marketing automation / customer journey) внутри лояльности Saby Retail/Presto. Позволяет настраивать многошаговые триггерные цепочки: отбор клиентов по условиям → действия (начисление бонусов, скидки, промокоды, рассылки) → ожидание события → повторное действие.

> [!info] Провенанс
> Задокументировано по скриншотам UI в источнике [[reaktivaciya-neaktivnyh-klientov-morozov-2026-07-03]] на примере одного сценария — «Давно не покупали» (см. [[Loyalty-Scenario-Reactivation-Inactive-Clients]]). Общий механизм ниже выведен из этого единственного walkthrough.

> [!warning] Дублирование с CustomerJourney-namespace
> Проект, к которому относится эта фича, называется **«Путь клиента»** и параллельно документируется другими агентами в вики под именами [[CustomerJourney-Project]] / [[CustomerJourney-Scenario-Builder]] / [[CustomerJourney-Scenario-Model]] — с существенно большей детализацией (архитектура, конкурентный бенчмарк Mindbox/REES46, платформа «Маршруты», модуль «Выборки»). Эта страница возникла из независимого источника в той же папке и не была смёржена с CustomerJourney-страницами на момент создания. Рекомендуется слияние на финальном проходе оркестратора — см. также раздел «Открытые вопросы» ниже, которые дословно взяты из ревью Морозова и отсутствуют в CustomerJourney-страницах.

## Расположение в продукте

Retail/Presto → левое меню → **Скидки и акции → Сценарии** (в одном ряду с пунктами: Бонусы, Промокоды, Реферальная система, Дисконтные карты — каждый блок лояльности отдельный пункт подменю).

## Список сценариев (дашборд раздела)

Верхнеуровневая статистика по всем сценариям: **Проходы** (общее число срабатываний, напр. 8 276), **В работе** (активные проходы, напр. 2 924); фильтры по типу: «Начисление бонусов» (5 сценариев), «Уведомления» (4 сценария).

Сценарии-шаблоны по умолчанию (демо-набор): Давно не покупали, Письмо с напоминанием, Брошенная корзина, День рождения, Бонусы при регистрации, Уведомление о начислении, Первая покупка, Сезонное (пример: зимняя обувь).

## Общие настройки (Общие настройки раздела)

Заполнены значениями по умолчанию, задают общие принципы взаимодействия с клиентом на уровне **всего раздела** (не отдельного сценария):

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| Частота попадания в сценарий | 30 дн | «Клиент попадает в сценарий не чаще N дн» — глобальный троттлинг |
| Ограничить срабатывание | включено | Новый сценарий не применяется к клиенту, ещё не прошедшему текущий |
| Режим тишины | включено | Срабатывание сценариев приостанавливается в указанный промежуток времени, в часовом поясе клиента |

## Типы сценария

При создании (кнопка «+») выбирается один из трёх типов:

1. **По событию** — условие запуска: действие клиента (покупка, вход на сайт, регистрация и т.п.). После выбора типа сразу открывается выбор конкретного события в меню (в отличие от периодического — минуя окно стартовых условий). *Не задокументирован по шагам в источнике 2026-07-03.*
2. **Периодический** — запускается с заданным временным интервалом (по умолчанию ежедневно в 12:00). Основной задокументированный тип.
3. **Разовый** — запускается один раз на выбранных клиентах (ручной отбор, не по расписанию).

## Стартовые условия (периодический сценарий)

Окно настройки после выбора типа «Периодический»:

1. **Периодичность** — по умолчанию заполнена (ежедневно, 12:00); для изменения — отдельное окно.
2. **Условия отбора клиентов** — конструктор логических условий **Если / И / ИЛИ**, категории:
   - Покупали / Не покупали
   - Что / Где (товар, точка продаж)
   - Физлица: Пол, Возраст, День рождения, Есть телефон, Есть Email
   - Когда (временное окно, напр. «за последние N дн»)
   - Количество / Число покупок
   - Владельцы карт / Без
   - Кол-во бонусов
   - Сумма
   - С последней покупки прошло

Сохранённые стартовые условия отображаются и редактируются на вкладке **«Описание»** сценария.

## Схема сценария (visual builder)

После сохранения стартовых условий сценарий открывается на вкладке **«Схема»** — канвас с узлами, старт которого — иконка флажка. По кнопке «+» добавляются блоки трёх типов:

### Действие
Список доступных действий: **Начислить бонусы**, **Назначить скидку**, **Выдать промокод**, **Отправить**, **Перенести в папку**, **Добавить тег**, **Выполнить код**.

- **Начислить бонусы** — указывается количество баллов. 
  > [!contradiction] Отсутствует поле «срок сгорания» бонусов, начисленных по сценарию — отмечено ревьюером как пробел (см. [[reaktivaciya-neaktivnyh-klientov-morozov-2026-07-03]]).
- **Отправить** — канал «Отправить по e-mail», поле «Выберите способ отправки…» (назначение поля не задокументировано и не понято ревьюером — открытый вопрос), «От кого» (имя отправителя), тело письма (текст).
- Один блок может содержать **несколько последовательных действий** — добавляются кнопкой «+действие» внутри того же блока (напр. Начислить бонусы + Отправить в одном шаге).

### Условие
Ветвление логики внутри схемы (тип блока присутствует в меню, детально не задокументирован в источнике).

### Ожидание
Блок паузы сценария:
- Задаётся срок ожидания в днях.
- Опциональное название блока.
- Ветка **«Если И/ИЛИ» → Событие** — выбор из каталога событий, сгруппированного по объектам:
  - **Клиент**: Отказ от покупки, Действия с карточкой клиента, Розничная покупка, Бронирование, Запись
  - **Посетитель сайта**: Вход на сайт
  - **Корзина**: Добавлен товар, Брошенная корзина, Заказ создан/изменён, Продукт добавлен в избранное, Окончена сессия
- Вторая, всегда присутствующая ветка — **«Время вышло»** (таймаут: событие не наступило за отведённый срок → альтернативный путь по схеме).

## Цели (Goals)

Отдельная сущность, привязываемая к сценарию (в источнике упомянута как элемент интерфейса — «Цели +», пример из скриншота: «Промо-акция сработала» с под-целями «Совершил покупку» / «Отказался от покупки»), позволяющая измерять эффективность сценария. В задокументированном walkthrough цели **не были заполнены** («Без целей пока») — то есть настройка целей опциональна и может быть добавлена отдельно от построения схемы.

## Запуск и работа сценария

- Сценарий сохраняется и запускается кнопкой «Запустить» (play-иконка).
- Работает **периодически**, в заданное время (по умолчанию 12:00).
- На каждом срабатывании: выполняется выборка по условиям отбора → возвращается список подходящих клиентов → из них отбираются **только новые** (которых ещё не было в сценарии) → они стартуют с первого узла схемы.
- Блоки схемы **до первого блока «Ожидание»** проходятся мгновенно, все за один раз.

## Вкладки раздела сценария

| Вкладка | Назначение |
|---|---|
| Описание | Стартовые условия (редактируемые) |
| Этапы | Упомянута, не раскрыта в источнике |
| Схема | Визуальный конструктор блоков |
| Проходы | Лог срабатываний; т.к. блоки до «Ожидания» проходят массово, **одна запись аккумулирует все события, прошедшие «за раз»** (не событие-на-клиента) |
| Статистика | Упомянута, не раскрыта в источнике |

## Открытые вопросы (из ревью Морозова)

См. полный разбор в [[reaktivaciya-neaktivnyh-klientov-morozov-2026-07-03]]. Ключевые:
- Нет настройки срока сгорания бонусов, начисленных сценарием.
- Неясно назначение поля «Выберите способ отправки…» в блоке «Отправить».
- Не задокументирован пошагово сценарий типа «По событию».
- Открыт вопрос, нужно ли обязательное условие «Покупали» (не только «Не покупали») в отборе для реактивационных сценариев — иначе в выборку могут попасть клиенты, которые никогда не совершали покупок.
- Макет окна стартовых условий на момент документирования не был финализирован («новое окно — макет нужен»).
