## Что выяснено по коду

- Прочитаны карточка и полная лента: предыдущих попыток исправления нет. Изучены скриншот и клиентский sbislogz со стенда test-online, сборка 26.6100-864 от 02.11.
- Bonus.GetSaleTotals определяет возврат по отрицательной TotalPrice. При полной оплате бонусами у продажи и возврата сумма 0: возврат попадает в покупки и увеличивает начисленные бонусы вместо компенсации списания.
- В ответе Bonus.GetSaleList чеки 4960/4961 имеют сумму 0, бонусы -50/+50, типы 0/1, Return=false/true. Обычный возврат 4963 имеет сумму -50 и правильно определяется по знаку.
- Пересчет пяти ноябрьских строк из лога по текущему правилу дал 4 покупки, сумму 180, начислено 50, списано 70 — совпало со скриншотом. По фактическому признаку возврата: 3 покупки, сумма 180, начислено 0, списано 20. Это проверка формул по логу, не запуск BL-метода на стенде.
- Заголовок месяца в LoyaltyProgram.GetGraphicData уже использует Sale.ListLight и SaleType, поэтому для розницы различает нулевой возврат. Существующие тесты GetSaleTotals проверяют ненулевые возвраты, но не эту границу.
- Связанный расчет возвратов внесен коммитом 9daecb1f40 от 14.09.2026. Лог не содержит отдельного вызова GetSaleTotals (возможна предзагрузка), поэтому факт вызова именно в этой сессии не установлен.
- Серверные логи за 05.11 не запрашивали: срок хранения 3 дня уже истек.

## Решения и почему

Согласовано: использовать существующий Sale.ListLight только для нулевых розничных чеков, не для всех продаж месяца. Основной SQL возвращает итоги и два упорядоченных массива: идентификаторы нулевых чеков и суммы их бонусов. Дополнительного SQL-сканирования месяца нет.

Для найденных нулевых возвратов уменьшаются счетчик покупок и начисления, корректируются списания. Поправка бонусов берется по модулю, поэтому работает и возврат списанных бонусов, и отмена начисленных. Модуль итогового списания берется после поправки, чтобы не терять знак при возврате покупок прошлого периода. Ненулевые и складские операции сохраняют прежнее поведение. Внешний контракт не меняется: служебные массивы не выходят из метода.

Добавлены три теста: полная оплата бонусами с возвратом, нулевая продажа без возврата, возврат за прошлый период с проверкой чтения типов только для нулевого чека. Существующий тест сравнения с графиком расширен нулевыми чеками со списанием и начислением.
